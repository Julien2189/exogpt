Notions modernes expliquées en détail

Cette version ajoute une explication plus poussée des syntaxes modernes que tu retrouves dans les démos : spread, rest, destructuration, template literals, callbacks, async/await, Promise.all, JSON, localStorage, DOM, classes CSS et transitions.

Objectif : ne pas seulement copier le code, mais comprendre pourquoi on utilise chaque syntaxe, quand elle est utile, et comment la réutiliser dans tes propres projets.

Spread operator ...

Le spread sert à déplier les éléments d'un tableau ou les propriétés d'un objet. Il est très utile pour faire des copies propres, fusionner des données ou ajouter/modifier une propriété sans toucher directement à l'objet d'origine.

javascript

          const base = {
            prenom: 'Julien',
            age: 32
          };

          // ...base copie toutes les propriétés de base dans un nouvel objet.
          // On ne modifie donc pas directement l'objet original.
          const enrichi = {
            ...base,
            ville: 'Lyon',
            age: 33 // Si une clé existe déjà, la dernière valeur gagne.
          };

          console.log(base);    // { prenom: 'Julien', age: 32 }
          console.log(enrichi); // { prenom: 'Julien', age: 33, ville: 'Lyon' }

Pourquoi utiliser le spread ?

  • Pour éviter de modifier directement une donnée d'origine.
  • Pour créer une copie avant de trier, filtrer ou transformer.
  • Pour fusionner plusieurs objets ou tableaux.
  • Pour écrire un code plus court et plus lisible.
javascript

          const notes = [12, 15, 18];

          // Copie du tableau.
          const copieNotes = [...notes];

          // Fusion de tableaux.
          const toutesLesNotes = [...notes, 20, 14];

          // Transformation sans toucher au tableau initial.
          const notesTriees = [...notes].sort((a, b) => a - b);

Rest operator ...

Le rest utilise aussi les trois points, mais son rôle est différent : il sert à regrouper ce qui reste. On le retrouve souvent dans les paramètres de fonction ou dans la destructuration.

javascript

          function additionner(...nombres) {
            // Ici ...nombres regroupe tous les arguments dans un tableau.
            return nombres.reduce((total, nombre) => total + nombre, 0);
          }

          console.log(additionner(5, 10, 15)); // 30
javascript

          const utilisateur = {
            prenom: 'Julien',
            age: 33,
            ville: 'Lyon',
            role: 'développeur'
          };

          // prenom est extrait.
          // ...infos garde toutes les autres propriétés dans un nouvel objet.
          const { prenom, ...infos } = utilisateur;

          console.log(prenom); // Julien
          console.log(infos);  // { age: 33, ville: 'Lyon', role: 'développeur' }

Différence entre spread et rest

Syntaxe Rôle Exemple
spread Déplie / copie / fusionne. { ...objet } ou [...tableau]
rest Regroupe ce qui reste. function f(...args) ou const { a, ...reste } = obj

Destructuration d'objet

La destructuration permet d'extraire rapidement des valeurs d'un objet ou d'un tableau. Elle évite d'écrire plusieurs fois objet.propriete.

javascript

          const user = {
            id: 1,
            prenom: 'Julien',
            profil: {
              niveau: 'avancé'
            }
          };

          // Sans destructuration :
          const prenomClassique = user.prenom;

          // Avec destructuration :
          const { id, prenom } = user;

          // On peut aussi renommer une variable.
          const { prenom: pseudo } = user;

          // On peut définir une valeur par défaut.
          const { role = 'visiteur' } = user;

          console.log(id, prenom, pseudo, role);

Intérêt de la destructuration

  • Code plus court.
  • Code plus lisible quand on manipule des objets.
  • Très pratique avec les réponses d'API.
  • Très utilisée dans React, Angular, Node.js et TypeScript.

Destructuration de tableau

Avec un tableau, la destructuration récupère les valeurs selon leur position.

javascript

          const couleurs = ['cyan', 'magenta', 'violet'];

          const [premiere, deuxieme] = couleurs;

          console.log(premiere); // cyan
          console.log(deuxieme); // magenta

          // On peut ignorer une valeur avec une virgule vide.
          const [, , troisieme] = couleurs;
          console.log(troisieme); // violet

Destructuration dans les paramètres de fonction

Très utile quand une fonction reçoit un objet de configuration.

javascript

          function afficherProfil({ prenom, age, ville = 'Non renseignée' }) {
            return `${prenom} a ${age} ans et habite à ${ville}.`;
          }

          const user = {
            prenom: 'Julien',
            age: 33
          };

          console.log(afficherProfil(user));

Template literals `...`

Les template literals permettent d'insérer des variables directement dans une chaîne avec ${variable}. Ils évitent les longues concaténations avec +.

javascript

          const nom = 'Julien';
          const score = 95;

          // Ancienne façon :
          const phrase1 = 'Bonjour ' + nom + ', ton score est ' + score;

          // Façon moderne :
          const phrase2 = `Bonjour ${nom}, ton score est ${score}`;

Arrow functions () => {}

Les fonctions fléchées sont une syntaxe courte pour écrire des fonctions anonymes. Elles sont très utilisées dans les callbacks : map, filter, forEach, addEventListener, Promise, etc.

javascript

          const nombres = [1, 2, 3];

          // map crée un nouveau tableau.
          const doubles = nombres.map(nombre => nombre * 2);

          // filter garde seulement les éléments qui respectent la condition.
          const grands = nombres.filter(nombre => nombre > 1);

Callback

Un callback est une fonction passée en argument à une autre fonction. On l'utilise quand une action doit être exécutée plus tard : clic, timer, réponse API, animation terminée.

javascript

          const bouton = document.querySelector('button');

          // La fonction passée à addEventListener est un callback.
          // Elle sera appelée uniquement quand l'utilisateur clique.
          bouton.addEventListener('click', () => {
            console.log('Bouton cliqué');
          });

Async / await

async et await permettent d'écrire du code asynchrone plus lisible. C'est essentiel pour les API, les timers, les opérations longues ou les accès serveur.

javascript

          async function chargerTodo() {
            try {
              const reponse = await fetch('https://jsonplaceholder.typicode.com/todos/1');

              if (!reponse.ok) {
                throw new Error(`Erreur HTTP ${reponse.status}`);
              }

              const data = await reponse.json();
              console.log(data);
            } catch (erreur) {
              console.error(erreur.message);
            }
          }

Promise.all

Promise.all lance plusieurs promesses en parallèle et attend que tout soit terminé. C'est plus rapide que d'attendre chaque tâche une par une, si les tâches ne dépendent pas les unes des autres.

javascript

          const [user, posts, comments] = await Promise.all([
            fetch('/api/user').then(r => r.json()),
            fetch('/api/posts').then(r => r.json()),
            fetch('/api/comments').then(r => r.json())
          ]);

JSON et localStorage

localStorage ne stocke que du texte. Pour sauvegarder un objet ou un tableau, il faut donc le transformer en chaîne JSON avec JSON.stringify, puis le reconstruire avec JSON.parse.

javascript

          const preference = {
            theme: 'cyberpunk',
            langue: 'fr'
          };

          // Sauvegarde : objet JS -> texte JSON.
          localStorage.setItem('preference', JSON.stringify(preference));

          // Lecture : texte JSON -> objet JS.
          const raw = localStorage.getItem('preference');
          const objet = JSON.parse(raw);

DOM, classes CSS et démos

Les démos utilisent souvent le DOM pour sélectionner un élément HTML, écouter un événement, ajouter une classe CSS, supprimer une classe ou modifier du texte.

javascript

          const menu = document.getElementById('menu');
          const bouton = document.getElementById('bouton');

          bouton.addEventListener('click', () => {
            // La classe CSS .open va changer l'apparence du menu.
            menu.classList.toggle('open');
          });

Transitions CSS

Une transition CSS rend un changement visuel plus doux. Au lieu de passer directement d'un état à l'autre, le navigateur anime progressivement la propriété.

css

          .carte {
            /* On demande au navigateur d'animer transform et opacity. */
            transition: transform 0.3s ease, opacity 0.3s ease;
          }

          .carte:hover {
            /* Au survol, la carte monte légèrement et devient un peu transparente. */
            transform: translateY(-4px);
            opacity: 0.9;
          }
// 01 — OBJETS

Les objets en JavaScript

Un objet est une collection de paires clé / valeur. C’est une structure essentielle en JavaScript, car elle permet de regrouper des données qui vont ensemble : un utilisateur, une recette, une dépense, une configuration, un produit, etc.

À quoi ça sert ?

Un objet sert à organiser des informations sous une forme lisible et logique. Par exemple, au lieu d’avoir plusieurs variables séparées comme prenom, age, ville, on peut tout regrouper dans un seul objet utilisateur.

Création et accès

Ici, on crée un objet utilisateur. Chaque information est stockée dans une propriété. Une propriété peut contenir une chaîne de caractères, un nombre, un booléen, un tableau, un autre objet ou même une fonction.

javascript

// On crée un objet nommé utilisateur.
// Un objet est entouré par des accolades { }.
const utilisateur = {
  // Propriété "prenom" avec une valeur de type string.
  prenom: 'Julien',

  // Propriété "age" avec une valeur de type number.
  age: 32,

  // Propriété booléenne : true ou false.
  estDeveloppeur: true,

  // Une propriété peut contenir un tableau.
  // Ici, on stocke plusieurs compétences.
  competences: ['JS', 'TS', 'Angular'],

  // Une propriété peut aussi contenir un autre objet.
  // On appelle ça un objet imbriqué.
  adresse: {
    ville: 'Lyon',
    codePostal: '69000'
  },

  // Une méthode est une fonction stockée dans un objet.
  // Ici, saluer() appartient à l'objet utilisateur.
  saluer() {
    // "this" représente l'objet actuel.
    // this.prenom signifie donc utilisateur.prenom.
    return `Salut, je suis ${this.prenom}`;
  }
};

// Accès avec la notation point.
// C'est la syntaxe la plus utilisée quand on connaît le nom de la propriété.
console.log(utilisateur.prenom);

// On peut accéder à une propriété d'un objet imbriqué.
// Ici : utilisateur -> adresse -> ville.
console.log(utilisateur.adresse.ville);

// Accès avec les crochets.
// Cette syntaxe est utile quand le nom de la propriété est dans une variable.
const cle = 'age';

// Ici, utilisateur[cle] revient à écrire utilisateur['age'].
console.log(utilisateur[cle]);

// On appelle la méthode saluer() de l'objet.
console.log(utilisateur.saluer());
Notation point ou crochets ?

Utilise objet.propriete quand tu connais directement le nom de la propriété. Utilise objet[variable] quand le nom de la propriété est dynamique ou stocké dans une variable.

Destructuring

La destructuration permet d’extraire rapidement des valeurs depuis un objet ou un tableau. Elle rend le code plus court, plus lisible et évite de répéter plusieurs fois le nom de l’objet.

À quoi ça sert ?

Au lieu d’écrire plusieurs lignes comme utilisateur.prenom, utilisateur.age, utilisateur.estDeveloppeur, on peut extraire directement ces propriétés dans des variables.

javascript

// On extrait directement les propriétés prenom, age et estDeveloppeur
// depuis l'objet utilisateur.
const { prenom, age, estDeveloppeur } = utilisateur;

// Maintenant, on peut utiliser directement les variables.
console.log(prenom);
console.log(age);
console.log(estDeveloppeur);

// On peut aussi renommer les variables pendant la destructuration.
// prenom devient nom.
// age devient annees.
const { prenom: nom, age: annees } = utilisateur;

console.log(nom);
console.log(annees);

// On peut donner une valeur par défaut.
// Si utilisateur.pays n'existe pas, alors pays vaudra 'France'.
const { pays = 'France' } = utilisateur;

console.log(pays);

// On peut destructurer un objet imbriqué.
// Ici, on récupère directement ville depuis utilisateur.adresse.
const {
  adresse: { ville }
} = utilisateur;

console.log(ville);

// La destructuration est très utile dans les paramètres de fonction.
// La fonction reçoit un objet, mais extrait seulement les valeurs utiles.
function afficherCarte({ prenom, age, adresse: { ville } }) {
  return `${prenom}, ${age} ans — ${ville}`;
}

// On passe l'objet complet à la fonction.
// La fonction récupère automatiquement prenom, age et adresse.ville.
console.log(afficherCarte(utilisateur));
Intérêt de la destructuration :

Elle est très utilisée quand tu travailles avec des API, des objets de configuration, des composants Angular/React, des tableaux d’objets ou des données JSON.

Spread / Rest

Les syntaxes ... peuvent avoir deux rôles différents selon le contexte : spread ou rest.

  • Spread : sert à étaler/copier les valeurs d’un objet ou d’un tableau.
  • Rest : sert à récupérer le reste des valeurs dans une variable.
Différence simple :

Le spread étale des données existantes. Le rest rassemble ce qu’il reste.

javascript

// Objet de départ.
const base = {
  prenom: 'Julien',
  age: 32
};

// SPREAD avec un objet.
// Ici, on crée une copie de base.
// Cela évite de modifier directement l'objet original.
const copie = { ...base };

console.log(copie);

// On peut utiliser le spread pour créer un nouvel objet enrichi.
// Les propriétés de base sont copiées dans enrichi.
const enrichi = {
  ...base,

  // On ajoute une nouvelle propriété.
  ville: 'Lyon',

  // Si une propriété existe déjà, la dernière valeur gagne.
  // Ici, age valait 32 dans base, mais il devient 33.
  age: 33
};

console.log(enrichi);

// REST avec un objet.
// Ici, on extrait prenom dans une variable.
// Le reste des propriétés est rangé dans l'objet autres.
const { prenom, ...autres } = enrichi;

console.log(prenom);
console.log(autres);

// REST dans une fonction.
// ...nombres récupère tous les arguments passés à la fonction
// et les transforme en tableau.
function somme(...nombres) {
  // reduce additionne tous les nombres du tableau.
  return nombres.reduce((a, b) => a + b, 0);
}

// Ici, les arguments 1, 2, 3, 4 deviennent le tableau [1, 2, 3, 4].
console.log(somme(1, 2, 3, 4));
Pourquoi utiliser spread ?

Le spread est très pratique pour créer une copie modifiée d’un objet sans toucher à l’original. C’est important quand tu veux éviter les effets de bord, par exemple dans une todo list, un panier, une liste de dépenses ou une application avec du localStorage.

Attention : { ...objet } fait une copie superficielle. Les objets imbriqués restent partagés par référence.
javascript

// Exemple de copie superficielle.
const profil = {
  prenom: 'Julien',
  adresse: {
    ville: 'Lyon'
  }
};

// On copie l'objet avec spread.
const copieProfil = { ...profil };

// Ici, on modifie l'objet imbriqué adresse.
copieProfil.adresse.ville = 'Paris';

// Problème : la ville change aussi dans profil,
// car adresse est un objet imbriqué partagé par référence.
console.log(profil.adresse.ville);
console.log(copieProfil.adresse.ville);

// Pour éviter ça, il faut aussi copier l'objet imbriqué.
const vraieCopie = {
  ...profil,
  adresse: {
    ...profil.adresse
  }
};

vraieCopie.adresse.ville = 'Marseille';

console.log(profil.adresse.ville);
console.log(vraieCopie.adresse.ville);

Méthodes Object essentielles

JavaScript fournit plusieurs méthodes utiles pour lire, transformer ou parcourir les objets. Elles sont très pratiques quand tu veux afficher des données dynamiquement dans le DOM.

javascript

// Objet contenant des statistiques.
const stats = {
  vues: 120,
  likes: 34,
  partages: 8
};

// Object.keys retourne un tableau avec toutes les clés de l'objet.
console.log(Object.keys(stats));
// Résultat : ['vues', 'likes', 'partages']

// Object.values retourne un tableau avec toutes les valeurs.
console.log(Object.values(stats));
// Résultat : [120, 34, 8]

// Object.entries retourne un tableau de paires [clé, valeur].
console.log(Object.entries(stats));
// Résultat : [['vues', 120], ['likes', 34], ['partages', 8]]

// Object.entries est très pratique avec une boucle for...of.
// À chaque tour, on récupère une clé et une valeur.
for (const [cle, valeur] of Object.entries(stats)) {
  console.log(`${cle} = ${valeur}`);
}

// Tableau de paires clé / valeur.
const arr = [
  ['a', 1],
  ['b', 2]
];

// Object.fromEntries fait l'inverse de Object.entries.
// Il transforme un tableau de paires en objet.
console.log(Object.fromEntries(arr));
// Résultat : { a: 1, b: 2 }

// Object.freeze bloque les modifications de premier niveau.
const config = Object.freeze({
  apiUrl: '/api'
});

// Cette modification ne fonctionnera pas.
// En mode strict, cela peut même provoquer une erreur.
config.apiUrl = '/x';

// La valeur reste '/api'.
console.log(config.apiUrl);
À retenir :

Object.keys() est utile pour récupérer les noms des propriétés. Object.values() sert à récupérer les valeurs. Object.entries() est très pratique pour parcourir un objet avec une boucle.

Classes modernes

Une classe sert à créer des objets avec une structure commune. Elle permet de regrouper des propriétés et des méthodes dans un modèle réutilisable.

À quoi ça sert ?

Une classe est utile quand tu dois créer plusieurs objets qui ont la même logique : des utilisateurs, des produits, des recettes, des dépenses, des tâches, des personnages, etc.

javascript

// Déclaration d'une classe.
// Une classe est comme un plan de fabrication pour créer des objets.
class Personne {
  // Propriété privée.
  // Le symbole # signifie que cette propriété n'est accessible
  // qu'à l'intérieur de la classe.
  #motDePasse;

  // Le constructor est appelé automatiquement quand on crée une instance.
  constructor(prenom, age, mdp) {
    // this.prenom crée une propriété prenom sur l'objet créé.
    this.prenom = prenom;

    // this.age crée une propriété age.
    this.age = age;

    // On stocke le mot de passe dans une propriété privée.
    this.#motDePasse = mdp;
  }

  // Méthode classique.
  // Toutes les instances de Personne pourront utiliser saluer().
  saluer() {
    return `Bonjour, je suis ${this.prenom}`;
  }

  // Getter.
  // Il permet d'utiliser estMajeur comme une propriété,
  // même si derrière c'est une fonction.
  get estMajeur() {
    return this.age >= 18;
  }

  // Setter.
  // Il permet de contrôler une modification.
  set nouvelAge(valeur) {
    // On vérifie que l'âge n'est pas négatif.
    if (valeur < 0) {
      throw new Error('Age invalide');
    }

    // Si la valeur est correcte, on modifie l'âge.
    this.age = valeur;
  }

  // Méthode statique.
  // Elle s'appelle directement sur la classe,
  // pas sur une instance.
  static creerAnonyme() {
    return new Personne('Anonyme', 0, '');
  }
}

// extends permet de créer une classe enfant.
// Developpeur hérite de Personne.
class Developpeur extends Personne {
  constructor(prenom, age, mdp, langage) {
    // super() appelle le constructor de la classe parent Personne.
    super(prenom, age, mdp);

    // On ajoute une propriété spécifique au développeur.
    this.langage = langage;
  }

  // Méthode propre à la classe Developpeur.
  presenter() {
    // On peut réutiliser saluer(), car Developpeur hérite de Personne.
    return `${this.saluer()}, je code en ${this.langage}`;
  }
}

// Création d'une instance de Developpeur.
// dev est un objet créé à partir de la classe Developpeur.
const dev = new Developpeur('Julien', 32, '***', 'JS');

// On appelle une méthode de l'objet dev.
console.log(dev.presenter());

// On utilise le getter estMajeur comme une propriété.
console.log(dev.estMajeur);
À retenir sur les classes :

Une classe permet de créer plusieurs objets similaires. constructor initialise l’objet. this représente l’objet en cours. extends permet l’héritage. super() appelle la classe parent.

L'objet Date

En JavaScript, l’objet Date représente un moment précis dans le temps. Il permet de créer, lire, comparer, formater ou calculer des dates.

À quoi ça sert ?

Les dates sont utiles dans beaucoup de projets : afficher une date de publication, calculer un âge, gérer un planning, enregistrer une opération, trier des dépenses, calculer une durée, créer un historique ou afficher une date au format français.

En interne, JavaScript stocke une date sous forme de timestamp : un nombre de millisecondes écoulées depuis le 1er janvier 1970 à 00:00:00 UTC.

Création et lecture

On peut créer une date de plusieurs façons : la date actuelle, une date écrite en texte, une date avec année/mois/jour, ou encore récupérer directement le timestamp actuel.

javascript

// Crée une date avec le moment actuel.
// Exemple : aujourd'hui à l'heure exacte où le code est exécuté.
const maintenant = new Date();

console.log(maintenant);

// Crée une date à partir d'une chaîne de caractères.
// Le format ISO est conseillé : année-mois-jour + heure.
const noel = new Date('2025-12-25T08:00:00');

console.log(noel);

// Crée une date avec des nombres.
// Attention : le mois commence à 0.
// 0 = janvier, 1 = février, 2 = mars, etc.
// Ici, 5 correspond donc à juin.
const dateNaissance = new Date(1990, 5, 15);

console.log(dateNaissance);

// Date.now() retourne le timestamp actuel.
// C'est le nombre de millisecondes depuis le 1er janvier 1970 UTC.
const timestamp = Date.now();

console.log(timestamp);

// getFullYear() retourne l'année complète.
// Exemple : 2025.
console.log(maintenant.getFullYear());

// getMonth() retourne le mois.
// Attention : les mois commencent à 0.
// Janvier = 0, décembre = 11.
console.log(maintenant.getMonth());

// getDate() retourne le jour du mois.
// Exemple : 25.
console.log(maintenant.getDate());

// getDay() retourne le jour de la semaine.
// Attention : dimanche = 0, lundi = 1, mardi = 2, etc.
console.log(maintenant.getDay());

// getHours() retourne l'heure.
console.log(maintenant.getHours());

// getMinutes() retourne les minutes.
console.log(maintenant.getMinutes());

// getTime() retourne le timestamp de cette date.
// C'est très utile pour comparer deux dates ou calculer une durée.
console.log(maintenant.getTime());
Piège classique : les mois sont 0-indexés en JavaScript. new Date(2025, 0, 1) correspond au 1er janvier 2025, alors que new Date(2025, 11, 1) correspond au 1er décembre 2025.
À retenir :

getMonth() ne retourne pas directement le numéro réel du mois. Si tu veux afficher le mois comme un humain, tu dois souvent faire getMonth() + 1.

Formatage moderne

Une date brute n’est pas toujours agréable à lire. Pour afficher une date proprement, on utilise souvent toLocaleDateString() ou l’objet moderne Intl.DateTimeFormat.

À quoi ça sert ?

Le formatage permet d’afficher une date selon la langue et le pays de l’utilisateur. Par exemple, en France on écrit souvent 25/12/2025, alors qu’aux États-Unis le format est plutôt 12/25/2025.

javascript

// On crée une date précise.
const d = new Date('2025-12-25T08:30:00');

// toLocaleDateString permet d'afficher une date dans un format local.
// 'fr-FR' signifie : français de France.
console.log(d.toLocaleDateString('fr-FR'));

// Intl.DateTimeFormat permet un formatage plus avancé.
// Il est très utile quand tu veux contrôler précisément l'affichage.
const formatLong = new Intl.DateTimeFormat('fr-FR', {
  // Affiche le jour de la semaine en toutes lettres.
  // Exemple : jeudi.
  weekday: 'long',

  // Affiche le jour du mois.
  // Exemple : 25.
  day: 'numeric',

  // Affiche le mois en toutes lettres.
  // Exemple : décembre.
  month: 'long',

  // Affiche l'année complète.
  // Exemple : 2025.
  year: 'numeric',

  // Affiche l'heure avec 2 chiffres.
  // Exemple : 08.
  hour: '2-digit',

  // Affiche les minutes avec 2 chiffres.
  // Exemple : 30.
  minute: '2-digit'
});

// format() applique la configuration définie au-dessus.
console.log(formatLong.format(d));

// Intl.RelativeTimeFormat sert à afficher une durée relative.
// Exemple : hier, demain, dans 3 jours, il y a 2 heures.
const rtf = new Intl.RelativeTimeFormat('fr-FR', {
  // numeric: 'auto' permet d'obtenir "hier" au lieu de "il y a 1 jour".
  numeric: 'auto'
});

// -1 signifie dans le passé.
// Ici : hier.
console.log(rtf.format(-1, 'day'));

// 3 signifie dans le futur.
// Ici : dans 3 jours.
console.log(rtf.format(3, 'day'));

// Ici : il y a 2 heures.
console.log(rtf.format(-2, 'hour'));
Intérêt de Intl :

Intl évite de formater les dates à la main. C’est plus fiable, plus propre, et ça s’adapte mieux aux langues, aux pays et aux formats locaux.

Calculs de dates

Pour calculer une différence entre deux dates, on utilise souvent leur timestamp. Comme une date peut être convertie en millisecondes, on peut faire des soustractions.

Exemple concret :

Dans une application de budget, tu peux calculer depuis combien de jours une dépense a été ajoutée. Dans une application de planning, tu peux calculer combien de jours restent avant un événement.

javascript

// Fonction qui calcule le nombre de jours entre deux dates.
function joursEntre(d1, d2) {
  // Quand on soustrait deux dates, JavaScript utilise leur timestamp.
  // Exemple : d2 - d1 donne une différence en millisecondes.
  const ms = Math.abs(d2 - d1);

  // Une journée contient :
  // 1000 millisecondes dans une seconde
  // 60 secondes dans une minute
  // 60 minutes dans une heure
  // 24 heures dans une journée
  const msParJour = 1000 * 60 * 60 * 24;

  // Math.floor arrondit vers le bas.
  // Cela évite d'avoir un résultat comme 3.8 jours.
  return Math.floor(ms / msParJour);
}

// Exemple d'utilisation.
const debut = new Date('2025-01-01');
const fin = new Date('2025-01-10');

console.log(joursEntre(debut, fin));

// Fonction qui ajoute un nombre de jours à une date.
function ajouterJours(date, jours) {
  // On crée une copie de la date.
  // C'est important pour ne pas modifier la date originale.
  const resultat = new Date(date);

  // getDate() récupère le jour du mois.
  // setDate() modifie le jour du mois.
  // Si on dépasse la fin du mois, JavaScript ajuste automatiquement.
  resultat.setDate(resultat.getDate() + jours);

  // On retourne la nouvelle date.
  return resultat;
}

// On calcule la date dans 30 jours à partir d'aujourd'hui.
const dans30j = ajouterJours(new Date(), 30);

console.log(dans30j);
Attention aux mutations :

Les méthodes comme setDate(), setMonth() ou setFullYear() modifient directement l’objet Date. C’est pour ça qu’on crée souvent une copie avec new Date(date) avant de faire un calcul.

Comparer et trier des dates

Les dates sont souvent utilisées pour trier des tableaux d’objets : dépenses, tâches, rendez-vous, opérations, historiques, messages, etc.

javascript

// Tableau d'objets contenant des dépenses.
const depenses = [
  { nom: 'Courses', montant: 45, date: '2025-04-10' },
  { nom: 'Essence', montant: 70, date: '2025-04-02' },
  { nom: 'Internet', montant: 30, date: '2025-04-18' }
];

// Pour trier par date, on transforme les chaînes en objets Date.
// new Date(a.date) - new Date(b.date) trie de la plus ancienne à la plus récente.
depenses.sort((a, b) => new Date(a.date) - new Date(b.date));

console.log(depenses);

// Pour trier de la plus récente à la plus ancienne,
// on inverse simplement l'ordre de la soustraction.
depenses.sort((a, b) => new Date(b.date) - new Date(a.date));

console.log(depenses);
À retenir :

Pour comparer deux dates, le plus simple est de comparer leurs timestamps. Plus le timestamp est grand, plus la date est récente.

// 03 — ASYNC / AWAIT

Code asynchrone — synchrone vs async

En JavaScript, le code est exécuté principalement sur un seul fil d’exécution côté interface. On dit souvent que JavaScript est mono-thread. Pourtant, il peut gérer des opérations longues comme les requêtes API, les timers, les lectures de fichiers ou les événements utilisateur sans bloquer toute la page.

À quoi ça sert l’asynchrone ?

Le code asynchrone sert à lancer une opération qui prend du temps sans bloquer le reste du programme. Par exemple, quand tu récupères des données avec fetch(), JavaScript ne doit pas figer toute la page en attendant la réponse du serveur.

Les opérations lentes sont déléguées au navigateur ou à Node.js : réseau, timers, événements, lecture de fichiers, base de données, etc. Quand l’opération est terminée, JavaScript récupère le résultat et continue le traitement.

Synchrone vs asynchrone

Un code synchrone s’exécute ligne par ligne. Chaque instruction attend que la précédente soit terminée. Un code asynchrone, lui, peut lancer une tâche et continuer le reste du programme pendant que cette tâche se termine.

javascript

// Exemple de code synchrone.
// Les lignes s'exécutent dans l'ordre.
console.log('Début');

console.log('Traitement immédiat');

console.log('Fin');

// Résultat :
// Début
// Traitement immédiat
// Fin
javascript

// Exemple de code asynchrone avec setTimeout.
console.log('Début');

// setTimeout programme une fonction qui sera exécutée plus tard.
// Ici, le callback sera exécuté après environ 1000 ms, donc 1 seconde.
setTimeout(() => {
  console.log('1 seconde plus tard');
}, 1000);

// JavaScript ne bloque pas ici.
// Il continue directement avec la ligne suivante.
console.log('Fin');

// Résultat :
// Début
// Fin
// 1 seconde plus tard
Point important :

setTimeout() ne bloque pas le programme. Il programme une action pour plus tard, puis JavaScript continue son exécution normale.

Callbacks

Un callback est une fonction passée en argument à une autre fonction. Elle sera appelée plus tard, souvent quand une opération est terminée.

À quoi ça sert ?

Les callbacks sont utiles pour réagir à un événement ou à une tâche terminée : clic sur un bouton, timer terminé, réponse reçue, animation terminée, etc.

javascript

// Cette fonction reçoit un callback en paramètre.
function chargerUtilisateur(callback) {
  // On simule une opération lente avec setTimeout.
  setTimeout(() => {
    const utilisateur = {
      id: 1,
      prenom: 'Julien'
    };

    // Quand les données sont prêtes,
    // on appelle le callback en lui passant l'utilisateur.
    callback(utilisateur);
  }, 1000);
}

// On appelle chargerUtilisateur.
// La fonction passée en argument est le callback.
chargerUtilisateur((user) => {
  console.log('Utilisateur chargé :', user);
});
Limite des callbacks :

Si on enchaîne trop de callbacks imbriqués, le code devient difficile à lire. On appelle parfois ça le callback hell.

Promises

Une Promise représente une valeur qui sera disponible plus tard. Elle peut réussir avec resolve ou échouer avec reject.

  • pending : la Promise est en attente.
  • fulfilled : la Promise a réussi.
  • rejected : la Promise a échoué.
javascript

// Fonction qui retourne une Promise.
function getUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      // Si l'id existe, on considère que la requête réussit.
      if (id) {
        resolve({
          id: id,
          prenom: 'Julien'
        });
      } else {
        // Sinon, on déclenche une erreur.
        reject('Utilisateur introuvable');
      }
    }, 1000);
  });
}

// then() s'exécute si la Promise réussit.
getUser(1)
  .then((user) => {
    console.log('Utilisateur reçu :', user);
  })
  .catch((err) => {
    // catch() récupère l'erreur si la Promise échoue.
    console.error('Erreur :', err);
  });
À quoi sert une Promise ?

Une Promise permet de gérer proprement une opération asynchrone. Elle évite d’avoir trop de callbacks imbriqués et permet d’enchaîner les traitements avec .then() et .catch().

Chaînage avec then / catch

On peut enchaîner plusieurs opérations asynchrones avec .then(). C’est utile quand une opération dépend du résultat de la précédente.

javascript

// Ces fonctions sont des exemples.
// Elles simulent des appels asynchrones comme des requêtes API.

function getUser(id) {
  return Promise.resolve({
    id: id,
    prenom: 'Julien'
  });
}

function getPosts(userId) {
  return Promise.resolve([
    { id: 101, titre: 'Premier article', userId: userId },
    { id: 102, titre: 'Deuxième article', userId: userId }
  ]);
}

function getComments(postId) {
  return Promise.resolve([
    { id: 1, message: 'Très bon article', postId: postId },
    { id: 2, message: 'Merci pour le partage', postId: postId }
  ]);
}

// On récupère d'abord un utilisateur.
getUser(1)

  // Ensuite, on récupère les posts de cet utilisateur.
  .then((user) => getPosts(user.id))

  // Ensuite, on récupère les commentaires du premier post.
  .then((posts) => getComments(posts[0].id))

  // Enfin, on affiche les commentaires.
  .then((comments) => console.log(comments))

  // Si une erreur arrive dans n'importe quelle étape,
  // elle sera récupérée ici.
  .catch((err) => console.error(err));
Limite :

Le chaînage avec .then() fonctionne très bien, mais quand la logique devient longue, async/await devient souvent plus lisible.

async / await

async/await est une syntaxe moderne qui rend le code asynchrone plus lisible. Elle permet d’écrire du code qui ressemble à du code synchrone, tout en restant asynchrone.

  • async devant une fonction signifie que cette fonction retourne toujours une Promise.
  • await attend la résolution d’une Promise.
  • try/catch permet de gérer les erreurs avec async/await.
javascript

// Une fonction async retourne toujours une Promise.
async function main() {
  try {
    // await attend que getUser(1) soit terminé.
    // La valeur résolue est stockée dans user.
    const user = await getUser(1);

    // Cette ligne attend les posts de l'utilisateur.
    const posts = await getPosts(user.id);

    // Cette ligne attend les commentaires du premier post.
    const comments = await getComments(posts[0].id);

    // Si tout s'est bien passé, on affiche les commentaires.
    console.log(comments);
  } catch (err) {
    // Si une erreur arrive dans un des await,
    // le code saute directement dans le catch.
    console.error(err);
  }
}

// On lance la fonction principale.
main();
Pourquoi utiliser async/await ?

Cette syntaxe est plus facile à lire quand tu dois faire plusieurs étapes : récupérer un utilisateur, récupérer ses données, traiter une réponse API, sauvegarder en base, afficher dans le DOM, etc.

Règles d'or

  • async devant une fonction signifie qu’elle retourne toujours une Promise, même si tu retournes une simple valeur.
  • await récupère la valeur résolue d’une Promise.
  • Si la Promise échoue, await déclenche une erreur récupérable avec try/catch.
  • Un await inutile peut ralentir toute une page.
  • Quand plusieurs opérations sont indépendantes, utilise Promise.all().
javascript

// Même si on retourne une simple chaîne,
// une fonction async retourne une Promise.
async function direBonjour() {
  return 'Bonjour Julien';
}

// Pour récupérer la valeur, on peut utiliser then().
direBonjour().then((message) => {
  console.log(message);
});

// Ou utiliser await dans une autre fonction async.
async function afficherMessage() {
  const message = await direBonjour();
  console.log(message);
}

afficherMessage();

Parallèle vs séquentiel

Une erreur fréquente est d’attendre plusieurs tâches une par une alors qu’elles pourraient être lancées en même temps.

Différence importante :

Le mode séquentiel attend chaque tâche avant de lancer la suivante. Le mode parallèle lance plusieurs tâches en même temps et attend que tout soit terminé.

javascript

// Fonction utilitaire qui simule une tâche longue.
// nom permet d'identifier la tâche.
// duree représente le temps d'attente en millisecondes.
function tache(nom, duree) {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(`Tâche ${nom} terminée`);
    }, duree);
  });
}

// Version séquentielle.
// Chaque await attend la fin de la tâche précédente.
// Durée totale approximative : 3 secondes.
async function sequentiel() {
  const a = await tache('A', 1000);
  const b = await tache('B', 1000);
  const c = await tache('C', 1000);

  return [a, b, c];
}

// Version parallèle.
// Les trois tâches sont lancées presque en même temps.
// Promise.all attend que les trois soient terminées.
// Durée totale approximative : 1 seconde.
async function parallele() {
  const [a, b, c] = await Promise.all([
    tache('A', 1000),
    tache('B', 1000),
    tache('C', 1000)
  ]);

  return [a, b, c];
}

// Exemple d'exécution.
sequentiel().then((resultat) => {
  console.log('Séquentiel :', resultat);
});

parallele().then((resultat) => {
  console.log('Parallèle :', resultat);
});
Anti-pattern : écrire plusieurs await l’un après l’autre alors que les tâches ne dépendent pas les unes des autres. Dans ce cas, Promise.all() est souvent plus performant.

Promise.all

Promise.all() permet d’exécuter plusieurs Promises en parallèle. Elle retourne une nouvelle Promise qui réussit quand toutes les Promises ont réussi.

javascript

// Exemple concret : charger plusieurs ressources indépendantes.
async function chargerDashboard() {
  try {
    // Les trois opérations sont lancées en même temps.
    const [user, stats, notifications] = await Promise.all([
      getUser(1),
      Promise.resolve({ vues: 120, likes: 34 }),
      Promise.resolve(['Message 1', 'Message 2'])
    ]);

    // Grâce à la destructuration tableau,
    // chaque résultat est rangé dans une variable.
    console.log(user);
    console.log(stats);
    console.log(notifications);
  } catch (err) {
    // Si une seule Promise échoue,
    // Promise.all échoue aussi.
    console.error('Erreur pendant le chargement :', err);
  }
}

chargerDashboard();
Attention :

Avec Promise.all(), si une seule Promise échoue, tout le groupe échoue. Si tu veux récupérer les résultats même quand certaines Promises échouent, tu peux utiliser Promise.allSettled().

Promise.allSettled

Promise.allSettled() attend que toutes les Promises soient terminées, même si certaines échouent. Elle donne le statut de chaque résultat.

javascript

// Promise réussie.
const succes = Promise.resolve('Donnée chargée');

// Promise échouée.
const erreur = Promise.reject('Erreur API');

// allSettled attend que toutes les Promises soient terminées.
Promise.allSettled([succes, erreur]).then((resultats) => {
  console.log(resultats);

  // Chaque résultat contient un statut :
  // fulfilled = réussi
  // rejected = échoué
  resultats.forEach((resultat) => {
    if (resultat.status === 'fulfilled') {
      console.log('Succès :', resultat.value);
    } else {
      console.log('Erreur :', resultat.reason);
    }
  });
});

fetch avec async/await

fetch() est l’une des utilisations les plus fréquentes de l’asynchrone. Il permet de faire une requête HTTP vers une API.

javascript

// Fonction async pour récupérer des données depuis une API.
async function chargerDonnees() {
  try {
    // fetch retourne une Promise.
    // await attend la réponse HTTP.
    const response = await fetch('https://jsonplaceholder.typicode.com/users/1');

    // response.ok vaut true si le statut HTTP est entre 200 et 299.
    if (!response.ok) {
      throw new Error('Erreur HTTP : ' + response.status);
    }

    // response.json() retourne aussi une Promise.
    // await récupère les données JSON converties en objet JavaScript.
    const data = await response.json();

    console.log(data);
  } catch (err) {
    // Erreur réseau, erreur HTTP ou erreur de conversion JSON.
    console.error('Impossible de charger les données :', err);
  }
}

chargerDonnees();
À retenir avec fetch :

fetch() ne déclenche pas automatiquement une erreur pour les statuts HTTP comme 404 ou 500. C’est pour ça qu’on vérifie souvent response.ok.

Mini démo pédagogique

Cette petite démo montre l’ordre d’exécution entre du code synchrone, un timer, une Promise et une fonction async.

javascript

// Première ligne synchrone.
console.log('1 - Début');

// setTimeout est asynchrone.
// Son callback est envoyé dans la file des timers.
setTimeout(() => {
  console.log('4 - setTimeout');
}, 0);

// Promise.resolve crée une Promise déjà résolue.
// Le then sera exécuté après le code synchrone,
// mais avant le setTimeout.
Promise.resolve().then(() => {
  console.log('3 - Promise');
});

// Dernière ligne synchrone.
console.log('2 - Fin');

// Résultat :
// 1 - Début
// 2 - Fin
// 3 - Promise
// 4 - setTimeout
Pourquoi la Promise passe avant setTimeout ?

Les callbacks de Promises sont placés dans la file des micro-tâches. Les timers comme setTimeout passent dans la file des macro-tâches. JavaScript traite les micro-tâches avant les timers.

Les Promises en profondeur

Une Promise représente une valeur qui n’est pas disponible immédiatement, mais qui le sera plus tard. Elle est très utilisée pour gérer du code asynchrone : requêtes API, timers, chargement de fichiers, base de données, etc.

À quoi ça sert ?

Une Promise sert à représenter une opération qui peut réussir ou échouer dans le futur. Par exemple : récupérer une liste d’utilisateurs depuis une API, charger des données JSON, attendre une animation, simuler un délai ou envoyer un formulaire.

Une Promise peut avoir trois états :

  • pending : la Promise est en attente, l’opération n’est pas encore terminée.
  • fulfilled : la Promise a réussi, elle retourne une valeur avec resolve.
  • rejected : la Promise a échoué, elle retourne une erreur avec reject.

Créer une Promise

Pour créer une Promise, on utilise new Promise(). Cette Promise reçoit une fonction avec deux paramètres : resolve et reject.

Différence simple :

resolve() signifie que l’opération a réussi. reject() signifie que l’opération a échoué.

javascript

// On crée une Promise.
// Elle représente une opération asynchrone qui sera terminée plus tard.
const promesse = new Promise((resolve, reject) => {
  // setTimeout simule une opération lente.
  // Ici, le code attend environ 800 millisecondes avant de répondre.
  setTimeout(() => {
    // Math.random() retourne un nombre entre 0 et 1.
    // Si ce nombre est supérieur à 0.5, on considère que l'opération réussit.
    const ok = Math.random() > 0.5;

    if (ok) {
      // resolve() signifie que la Promise réussit.
      // La valeur 'Donnée OK' sera envoyée au .then().
      resolve('Donnée OK');
    } else {
      // reject() signifie que la Promise échoue.
      // L'erreur sera envoyée au .catch().
      reject(new Error('Échec aléatoire'));
    }
  }, 800);
});

// On consomme la Promise avec then / catch / finally.
promesse
  .then((valeur) => {
    // then() s'exécute uniquement si la Promise réussit.
    // La variable valeur contient ce qui a été passé à resolve().
    console.log('✓', valeur);
  })
  .catch((erreur) => {
    // catch() s'exécute si la Promise échoue.
    // La variable erreur contient ce qui a été passé à reject().
    console.error('✗', erreur.message);
  })
  .finally(() => {
    // finally() s'exécute dans tous les cas :
    // réussite ou échec.
    // Très utile pour cacher un loader, réactiver un bouton, etc.
    console.log('Terminé');
  });
À retenir :

.then() récupère le succès, .catch() récupère l’erreur, et .finally() s’exécute quoi qu’il arrive.

Exemple concret : simuler une API

Les Promises sont souvent utilisées pour représenter une requête API. Dans cet exemple, on simule une API qui retourne un utilisateur après un court délai.

javascript

// Fonction qui simule une requête API.
function chargerUtilisateur(id) {
  // La fonction retourne une Promise.
  // Cela veut dire que le résultat arrivera plus tard.
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      // Si aucun id n'est fourni, on renvoie une erreur.
      if (!id) {
        reject(new Error('ID utilisateur manquant'));
        return;
      }

      // Sinon, on renvoie un faux utilisateur.
      resolve({
        id: id,
        prenom: 'Julien',
        role: 'Développeur'
      });
    }, 1000);
  });
}

// On appelle la fonction.
// Elle ne retourne pas directement l'utilisateur,
// elle retourne une Promise.
chargerUtilisateur(1)
  .then((utilisateur) => {
    // Ici, on récupère l'utilisateur quand la Promise réussit.
    console.log(utilisateur);
  })
  .catch((erreur) => {
    // Ici, on récupère l'erreur si la Promise échoue.
    console.error(erreur.message);
  });

Chaîner plusieurs Promises

On peut chaîner plusieurs .then() quand une étape dépend du résultat de la précédente. Par exemple : charger un utilisateur, puis charger ses articles, puis charger les commentaires du premier article.

javascript

// Cette fonction retourne une Promise avec un utilisateur.
function getUser(id) {
  return Promise.resolve({
    id: id,
    prenom: 'Julien'
  });
}

// Cette fonction retourne une Promise avec les articles d'un utilisateur.
function getPosts(userId) {
  return Promise.resolve([
    { id: 101, titre: 'Article JS', userId: userId },
    { id: 102, titre: 'Article TypeScript', userId: userId }
  ]);
}

// Cette fonction retourne une Promise avec les commentaires d'un article.
function getComments(postId) {
  return Promise.resolve([
    { id: 1, message: 'Super cours', postId: postId },
    { id: 2, message: 'Très clair', postId: postId }
  ]);
}

// Étape 1 : on récupère l'utilisateur.
getUser(1)

  // Étape 2 : on récupère les articles de cet utilisateur.
  // Le return est important : il permet de transmettre la Promise suivante.
  .then((user) => {
    return getPosts(user.id);
  })

  // Étape 3 : on récupère les commentaires du premier article.
  .then((posts) => {
    return getComments(posts[0].id);
  })

  // Étape 4 : on affiche les commentaires.
  .then((comments) => {

// 04 — PROMISES

Les Promises en profondeur

Une Promise représente une valeur qui n’est pas disponible immédiatement, mais qui le sera plus tard. Elle est très utilisée pour gérer du code asynchrone : requêtes API, timers, chargement de fichiers, base de données, etc.

À quoi ça sert ?

Une Promise sert à représenter une opération qui peut réussir ou échouer dans le futur. Par exemple : récupérer une liste d’utilisateurs depuis une API, charger des données JSON, attendre une animation, simuler un délai ou envoyer un formulaire.

Une Promise peut avoir trois états :

  • pending : la Promise est en attente, l’opération n’est pas encore terminée.
  • fulfilled : la Promise a réussi, elle retourne une valeur avec resolve.
  • rejected : la Promise a échoué, elle retourne une erreur avec reject.

Créer une Promise

Pour créer une Promise, on utilise new Promise(). Cette Promise reçoit une fonction avec deux paramètres : resolve et reject.

Différence simple :

resolve() signifie que l’opération a réussi. reject() signifie que l’opération a échoué.

javascript

// On crée une Promise.
// Elle représente une opération asynchrone qui sera terminée plus tard.
const promesse = new Promise((resolve, reject) => {
  // setTimeout simule une opération lente.
  // Ici, le code attend environ 800 millisecondes avant de répondre.
  setTimeout(() => {
    // Math.random() retourne un nombre entre 0 et 1.
    // Si ce nombre est supérieur à 0.5, on considère que l'opération réussit.
    const ok = Math.random() > 0.5;

    if (ok) {
      // resolve() signifie que la Promise réussit.
      // La valeur 'Donnée OK' sera envoyée au .then().
      resolve('Donnée OK');
    } else {
      // reject() signifie que la Promise échoue.
      // L'erreur sera envoyée au .catch().
      reject(new Error('Échec aléatoire'));
    }
  }, 800);
});

// On consomme la Promise avec then / catch / finally.
promesse
  .then((valeur) => {
    // then() s'exécute uniquement si la Promise réussit.
    // La variable valeur contient ce qui a été passé à resolve().
    console.log('✓', valeur);
  })
  .catch((erreur) => {
    // catch() s'exécute si la Promise échoue.
    // La variable erreur contient ce qui a été passé à reject().
    console.error('✗', erreur.message);
  })
  .finally(() => {
    // finally() s'exécute dans tous les cas :
    // réussite ou échec.
    // Très utile pour cacher un loader, réactiver un bouton, etc.
    console.log('Terminé');
  });
À retenir :

.then() récupère le succès, .catch() récupère l’erreur, et .finally() s’exécute quoi qu’il arrive.

Exemple concret : simuler une API

Les Promises sont souvent utilisées pour représenter une requête API. Dans cet exemple, on simule une API qui retourne un utilisateur après un court délai.

javascript

// Fonction qui simule une requête API.
function chargerUtilisateur(id) {
  // La fonction retourne une Promise.
  // Cela veut dire que le résultat arrivera plus tard.
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      // Si aucun id n'est fourni, on renvoie une erreur.
      if (!id) {
        reject(new Error('ID utilisateur manquant'));
        return;
      }

      // Sinon, on renvoie un faux utilisateur.
      resolve({
        id: id,
        prenom: 'Julien',
        role: 'Développeur'
      });
    }, 1000);
  });
}

// On appelle la fonction.
// Elle ne retourne pas directement l'utilisateur,
// elle retourne une Promise.
chargerUtilisateur(1)
  .then((utilisateur) => {
    // Ici, on récupère l'utilisateur quand la Promise réussit.
    console.log(utilisateur);
  })
  .catch((erreur) => {
    // Ici, on récupère l'erreur si la Promise échoue.
    console.error(erreur.message);
  });

localStorage & sessionStorage

Le Web Storage API permet de stocker des données directement dans le navigateur. C’est très pratique pour conserver des préférences, des formulaires, des tâches, des dépenses, un panier, un thème sombre, ou des données temporaires côté client.

À quoi ça sert ?

Le stockage navigateur permet de garder des données même après une action utilisateur. Par exemple, dans une todo list, tu peux sauvegarder les tâches pour les retrouver au prochain chargement de la page.

Il existe deux stockages principaux : localStorage et sessionStorage. Ils fonctionnent presque pareil, mais leur durée de conservation est différente.

Différences clés

Caractéristique localStorage sessionStorage
Persistance Reste enregistré jusqu’à suppression manuelle. Reste seulement tant que l’onglet est ouvert.
Partage entre onglets Oui, pour le même site. Non, chaque onglet a sa propre session.
Type des valeurs Chaînes de caractères uniquement.
Usage typique Préférences, thème, panier, todo list, données utilisateur non sensibles. Formulaire temporaire, étape de navigation, données de session courtes.
Point très important :

localStorage et sessionStorage stockent uniquement du texte. Pour stocker un objet ou un tableau, il faut le transformer en JSON avec JSON.stringify(), puis le relire avec JSON.parse().

API de base

L’API de base est simple : on peut enregistrer, lire, supprimer une clé ou tout effacer. Chaque donnée est stockée sous forme de paire clé / valeur.

javascript

// setItem() permet d'enregistrer une donnée.
// Le premier paramètre est la clé.
// Le deuxième paramètre est la valeur à stocker.
localStorage.setItem('theme', 'cyberpunk');

// getItem() permet de récupérer une donnée grâce à sa clé.
// Si la clé n'existe pas, getItem() retourne null.
const theme = localStorage.getItem('theme');

console.log(theme);

// removeItem() supprime une seule donnée grâce à sa clé.
localStorage.removeItem('theme');

// clear() supprime toutes les données du localStorage
// pour le domaine actuel.
// Attention : cela efface tout ce que ton site a stocké.
localStorage.clear();

// localStorage.length donne le nombre d'éléments stockés.
console.log(localStorage.length);

// On peut parcourir toutes les clés du localStorage.
for (let i = 0; i < localStorage.length; i++) {
  // key(i) récupère le nom de la clé à l'index donné.
  const cle = localStorage.key(i);

  // Une fois la clé récupérée, on peut lire sa valeur.
  console.log(cle, localStorage.getItem(cle));
}
À retenir :

setItem() écrit une donnée, getItem() lit une donnée, removeItem() supprime une donnée, et clear() vide tout le stockage du site.

sessionStorage

sessionStorage fonctionne comme localStorage, mais les données disparaissent quand l’onglet est fermé.

javascript

// On enregistre une donnée temporaire dans sessionStorage.

// On récupère cette donnée.

Quand utiliser sessionStorage ?

Utilise sessionStorage pour des données temporaires : une étape de formulaire, une recherche en cours, un état provisoire ou une donnée qui ne doit pas rester après la fermeture de l’onglet.

Stocker des objets

Le stockage navigateur ne garde que des chaînes de caractères. Donc si tu veux stocker un objet JavaScript, tu dois d’abord le convertir en JSON.

javascript

// Objet JavaScript classique.
const user = {
  prenom: 'Julien',
  age: 32
};

// JSON.stringify() transforme l'objet JavaScript en chaîne JSON.
// C'est obligatoire pour le stocker dans localStorage.
localStorage.setItem('user', JSON.stringify(user));

// getItem() récupère la chaîne JSON stockée.
const userJSON = localStorage.getItem('user');

// JSON.parse() transforme la chaîne JSON en objet JavaScript.
const recup = JSON.parse(userJSON);

// Maintenant, on peut accéder aux propriétés normalement.
console.log(recup.prenom);
console.log(recup.age);
JSON.stringify / JSON.parse :

JSON.stringify() transforme un objet en texte JSON. JSON.parse() transforme un texte JSON en objet JavaScript. Ce duo est indispensable avec localStorage.

Stocker un tableau

On utilise exactement la même logique pour un tableau. C’est très utile pour une todo list, une liste de dépenses, un panier ou une liste de recettes.

javascript

// Tableau d'objets.
const taches = [
  { texte: 'Apprendre localStorage', fait: false },
  { texte: 'Créer une todo list', fait: true }
];

// On convertit le tableau en JSON avant de le stocker.
localStorage.setItem('taches', JSON.stringify(taches));

// On récupère la valeur stockée.
const tachesSauvees = localStorage.getItem('taches');

// On retransforme le JSON en tableau JavaScript.
// Si rien n'est stocké, on utilise un tableau vide par défaut.
const tachesRecuperees = JSON.parse(tachesSauvees) || [];

console.log(tachesRecuperees);
Attention :

Si localStorage.getItem() retourne null, alors JSON.parse(null) retourne null. Pour éviter les bugs, on utilise souvent || [] ou || {} selon le type attendu.

Exemple concret : mini sauvegarde de préférences

Voici un exemple simple pour sauvegarder les préférences d’un utilisateur.

javascript

const preferences = {
  theme: 'dark',
  langue: 'fr',
  sidebarOuverte: true

Wrapper sécurisé

Un wrapper est un objet ou une fonction qui simplifie l’utilisation de localStorage. Il évite de répéter partout JSON.stringify(), JSON.parse() et les try/catch.

Pourquoi sécuriser ?

Le stockage peut échouer dans certains cas : navigation privée, quota dépassé, JSON invalide, stockage désactivé ou donnée corrompue. Le wrapper permet d’éviter que toute l’application plante.

javascript

// Objet utilitaire pour gérer localStorage proprement.
const storage = {
  // Méthode get() pour lire une valeur.
  // cle = nom de la donnée à lire.
  // defaut = valeur retournée si la donnée n'existe pas ou si une erreur arrive.
  get(cle, defaut = null) {
    try {
      // On récupère la donnée brute.
      const raw = localStorage.getItem(cle);

      // Si la clé n'existe pas, getItem() retourne null.
      // Dans ce cas, on retourne la valeur par défaut.
      if (raw === null) {
        return defaut;
      }

      // Sinon, on transforme le JSON en vraie valeur JavaScript.
      return JSON.parse(raw);
    } catch (err) {
      // Si JSON.parse échoue ou si localStorage est indisponible,
      // on retourne la valeur par défaut au lieu de faire planter l'application.
      console.warn('Lecture storage impossible:', err);
      return defaut;
    }
  },

  // Méthode set() pour enregistrer une valeur.
  set(cle, valeur) {
    try {
      // On convertit la valeur en JSON avant stockage.
      localStorage.setItem(cle, JSON.stringify(valeur));

      // On retourne true pour dire que la sauvegarde a réussi.
      return true;
    } catch (err) {
      // Si le stockage échoue, on affiche un avertissement.
      console.warn('Storage indisponible:', err);

      // On retourne false pour indiquer l'échec.
      return false;
    }
  },

  // Méthode remove() pour supprimer une clé.
  remove(cle) {
    try {
      localStorage.removeItem(cle);
    } catch (err) {
      console.warn('Suppression storage impossible:', err);
    }
  }
};

// On sauvegarde un objet avec le wrapper.
storage.set('preferences', {
  theme: 'dark',
  lang: 'fr'
});

// On récupère les préférences.
// Si rien n'existe, on utilise les valeurs par défaut.
const prefs = storage.get('preferences', {
  theme: 'light',
  lang: 'en'
});

console.log(prefs);
Intérêt du wrapper :

Ton code devient plus propre. Au lieu de refaire JSON.stringify(), JSON.parse() et try/catch partout, tu utilises simplement storage.set(), storage.get() et storage.remove().

Mettre à jour avec spread

Le spread est très utile avec le stockage, car il permet de créer une nouvelle version d’un tableau ou d’un objet sans modifier directement l’ancien.

javascript

// Tableau existant.

// Nouvelle tâche à ajouter.

  texte: 'Comprendre le spread',
  fait: false
};

// SPREAD avec un tableau.
// On crée un nouveau tableau contenant toutes les anciennes tâches,
// puis on ajoute la nouvelle tâche à la fin.
const nouvellesTaches = [...anciennesTaches, nouvelleTache];

// On sauvegarde le nouveau tableau.

// SPREAD avec un objet.
// On crée une nouvelle version d'une tâche en modifiant seulement fait.
const tacheModifiee = {
  ...nouvelleTache,
  fait: true
};

console.log(tacheModifiee);
Pourquoi utiliser spread ici ?

Le spread rend le code plus clair pour créer une nouvelle version d’une donnée. C’est très utile quand tu veux éviter de modifier directement une variable ou préparer ton code pour des frameworks comme React, Angular ou Vue.

Sécurité :

Ne stocke jamais de mot de passe ou de token très sensible en longue durée dans localStorage. Si un script malveillant est injecté dans la page avec une faille XSS, il peut lire le contenu du stockage.

Événement storage

L’événement storage se déclenche quand une donnée du localStorage est modifiée depuis un autre onglet du même site.

À quoi ça sert ?

Cela permet de synchroniser plusieurs onglets. Par exemple, si l’utilisateur change de thème dans un onglet, tu peux mettre à jour automatiquement les autres onglets ouverts.

javascript

// On écoute l'événement storage sur window.
// Il se déclenche quand le localStorage est modifié
// depuis un autre onglet du même domaine.
window.addEventListener('storage', (event) => {
  // event.key contient le nom de la clé modifiée.
  console.log('Clé modifiée:', event.key);

  // event.oldValue contient l'ancienne valeur.
  console.log('Ancienne valeur:', event.oldValue);

  // event.newValue contient la nouvelle valeur.
  console.log('Nouvelle valeur:', event.newValue);

  // event.storageArea indique si cela vient de localStorage ou sessionStorage.
  console.log('Zone de stockage:', event.storageArea);

  // event.url indique l'URL de la page qui a déclenché le changement.
  console.log('Page source:', event.url);
});
Petit piège :

L’événement storage ne se déclenche généralement pas dans l’onglet qui fait la modification. Il se déclenche surtout dans les autres onglets ouverts sur le même site.

Notions avancées JavaScript

Ces notions permettent de passer d’un JavaScript de base à un JavaScript plus solide, plus propre et plus professionnel. Tu les retrouveras dans les frameworks modernes, les librairies, les projets complexes, les API, les architectures front-end et les applications réelles.

À quoi ça sert ?

Ces concepts servent à mieux organiser ton code, éviter les bugs difficiles, comprendre les librairies modernes, créer des fonctions réutilisables, manipuler des objets avancés et écrire un JavaScript plus robuste.

Closures

Une closure apparaît quand une fonction garde accès aux variables de son environnement, même après l’exécution de la fonction extérieure.

À quoi ça sert ?

Les closures permettent de créer une mémoire privée. C’est utile pour faire des compteurs, cacher des données, créer des fonctions configurées ou éviter d’exposer certaines variables dans le scope global.

javascript

// Fonction qui crée un compteur.
// Elle contient une variable privée n.
function creerCompteur() {
  // Cette variable appartient à creerCompteur().
  // Elle n'est pas accessible directement depuis l'extérieur.
  let n = 0;

  // On retourne un objet contenant plusieurs méthodes.
  // Ces méthodes gardent accès à la variable n grâce à la closure.
  return {
    // Incrémente n puis retourne sa nouvelle valeur.
    incrementer: () => ++n,

    // Retourne la valeur actuelle de n.
    valeur: () => n,

    // Remet n à zéro.
    reset: () => {
      n = 0;
    }
  };
}

// On crée un compteur.
const c = creerCompteur();

// On incrémente deux fois.
c.incrementer();
c.incrementer();

// On affiche la valeur actuelle.
// Résultat : 2.
console.log(c.valeur());

// Impossible d'accéder directement à n.
// console.log(c.n) donnera undefined.
Pourquoi c’est puissant ?

La variable n est protégée. Elle ne peut être modifiée qu’avec les méthodes incrementer(), valeur() et reset(). C’est une forme simple d’encapsulation.

this, bind, call, apply

Le mot-clé this représente le contexte d’exécution d’une fonction. Sa valeur dépend de la manière dont la fonction est appelée.

Point important :

this ne dépend pas forcément de l’endroit où la fonction est écrite, mais surtout de la manière dont elle est appelée.

javascript

// Objet avec une propriété nom et une méthode saluer.
const obj = {
  nom: 'Lizzie',

  // Fonction classique.
  // Ici, this représente l'objet qui appelle la méthode.
  saluer: function () {
    return `Hi ${this.nom}`;
  }
};

// Ici, saluer() est appelée depuis obj.
// Donc this vaut obj.
console.log(obj.saluer());
// Résultat : Hi Lizzie

// On copie la fonction dans une variable.
const fn = obj.saluer;

// Ici, la fonction n'est plus appelée depuis obj.
// Le this est perdu.
// En mode strict, this peut valoir undefined.
console.log(fn());

// bind() crée une nouvelle fonction avec this fixé définitivement.
// Ici, on force this à être obj.
const liee = obj.saluer.bind(obj);

// Même si on appelle liee seule,
// this reste lié à obj.
console.log(liee());
// Résultat : Hi Lizzie

// call() appelle immédiatement la fonction
// en choisissant manuellement la valeur de this.
console.log(obj.saluer.call({ nom: 'Tibo' }));
// Résultat : Hi Tibo

// apply() ressemble à call().
// La différence est surtout utile quand on passe des arguments sous forme de tableau.
function presenter(langage, niveau) {
  return `${this.nom} code en ${langage} niveau ${niveau}`;
}

// Avec call(), les arguments sont passés un par un.
console.log(presenter.call({ nom: 'Julien' }, 'JavaScript', 'avancé'));

// Avec apply(), les arguments sont passés dans un tableau.
console.log(presenter.apply({ nom: 'Julien' }, ['TypeScript', 'intermédiaire']));
Résumé rapide :

bind() crée une nouvelle fonction avec un this fixé. call() appelle une fonction avec un this choisi. apply() fait pareil que call(), mais avec les arguments dans un tableau.

Map & Set

Map et Set sont deux structures de données modernes. Elles ressemblent aux objets et aux tableaux, mais avec des comportements plus adaptés à certains cas.

À quoi sert Map ?

Map sert à stocker des paires clé / valeur, comme un objet, mais avec plus de souplesse. Les clés peuvent être des chaînes, des nombres, des objets, des fonctions, etc.

À quoi sert Set ?

Set sert à stocker des valeurs uniques. Il supprime automatiquement les doublons.

javascript

// Création d'une Map.
// Une Map stocke des paires clé / valeur.
const cache = new Map();

// set() ajoute une valeur dans la Map.
// Ici, la clé est une chaîne.
cache.set('cle-string', 1);

// Une clé peut aussi être un nombre.
cache.set(42, 'nombre comme clé');

// Une clé peut même être un objet.
const objCle = {};
cache.set(objCle, 'objet comme clé');

// get() récupère une valeur grâce à sa clé.
console.log(cache.get(42));
// Résultat : nombre comme clé

// has() vérifie si une clé existe dans la Map.
console.log(cache.has(objCle));
// Résultat : true

// delete() supprime une entrée.
cache.delete('cle-string');

// size donne le nombre d'éléments.
console.log(cache.size);

// On peut parcourir une Map avec for...of.
for (const [cle, valeur] of cache) {
  console.log(cle, valeur);
}

// Création d'un Set.
// Un Set ne garde que les valeurs uniques.
const tags = new Set(['js', 'ts', 'js']);

// Le doublon 'js' est automatiquement supprimé.
console.log(tags);

// add() ajoute une valeur.
tags.add('css');

// has() vérifie si une valeur existe.
console.log(tags.has('css'));

// Exemple très courant : supprimer les doublons d'un tableau.
const uniques = [...new Set([1, 2, 2, 3, 3, 3])];

// Ici, on utilise :
// 1. new Set(...) pour supprimer les doublons.
// 2. le spread [...] pour transformer le Set en tableau.
console.log(uniques);
// Résultat : [1, 2, 3]
Quand utiliser Map ou Set ?

Utilise Map quand tu veux associer des clés à des valeurs avec plus de liberté qu’un objet classique. Utilise Set quand tu veux éviter les doublons.

Symbols

Un Symbol est une valeur unique. Même si deux Symbols ont la même description, ils restent différents.

À quoi ça sert ?

Les Symbols sont utiles pour créer des clés d’objet uniques, éviter les collisions de noms ou stocker des métadonnées plus discrètes dans un objet.

javascript

// Création de deux Symbols avec la même description.
const id1 = Symbol('id');
const id2 = Symbol('id');

// Même si la description est identique,
// les deux Symbols sont différents.
console.log(id1 === id2);
// Résultat : false

// On crée un Symbol pour stocker des métadonnées.
const META = Symbol('meta');

// Objet classique.
const doc = {
  titre: 'Cours',

  // Les crochets permettent d'utiliser la valeur du Symbol comme clé.
  [META]: {
    version: 1
  }
};

// Object.keys() ne retourne que les clés classiques.
// Les clés Symbol ne sont pas listées ici.
console.log(Object.keys(doc));
// Résultat : ['titre']

// Pour récupérer les Symbols d'un objet,
// on peut utiliser Object.getOwnPropertySymbols().
console.log(Object.getOwnPropertySymbols(doc));

// On peut accéder à la propriété Symbol si on possède la référence META.
console.log(doc[META]);
Attention :

Les Symbols ne rendent pas une donnée totalement privée. Ils la rendent surtout moins accessible par les méthodes classiques comme Object.keys().

Generators

Un generator est une fonction spéciale qui peut mettre son exécution en pause avec yield, puis reprendre plus tard.

À quoi ça sert ?

Les generators sont utiles pour produire des valeurs une par une, créer des séquences, parcourir de grosses données progressivement ou contrôler finement l’exécution d’une fonction.

javascript

// Le symbole * indique que cette fonction est un generator.
function* compteur() {
  let n = 0;

  // Boucle infinie.
  // Elle ne bloque pas tout le programme grâce à yield.
  while (true) {
    // yield retourne une valeur
    // puis met la fonction en pause.
    yield ++n;
  }
}

// On crée un generator.
const g = compteur();

// next() reprend l'exécution jusqu'au prochain yield.
console.log(g.next().value);
// Résultat : 1

console.log(g.next().value);
// Résultat : 2

console.log(g.next().value);
// Résultat : 3

// Chaque appel à next() continue là où le generator s'était arrêté.
javascript

// Autre exemple : générer une liste limitée.
function* nombresPairs(max) {
  for (let i = 0; i <= max; i += 2) {
    yield i;
  }
}

// On peut parcourir un generator avec for...of.
for (const nombre of nombresPairs(10)) {
  console.log(nombre);
}

// Résultat :
// 0
// 2
// 4
// 6
// 8
// 10
À retenir :

Une fonction normale retourne une valeur avec return et se termine. Un generator peut retourner plusieurs valeurs dans le temps avec yield.

Proxy & Reflect

Un Proxy permet d’intercepter des opérations sur un objet : lecture, écriture, suppression, vérification de propriété, etc.

À quoi ça sert ?

Les Proxies permettent de surveiller ou modifier le comportement d’un objet. Ils peuvent servir à faire de la validation, du debug, de la réactivité, des logs ou des objets avec valeurs par défaut.

javascript

// Objet cible.
// C'est l'objet réel que le Proxy va surveiller.
const cible = {
  x: 1
};

// Création du Proxy.
// Le premier argument est l'objet cible.
// Le deuxième argument est un handler avec des pièges : get, set, etc.
const proxy = new Proxy(cible, {
  // get() intercepte la lecture d'une propriété.
  get(obj, prop) {
    // prop est le nom de la propriété lue.
    console.log(`[GET] ${String(prop)}`);

    // Reflect.get() lit réellement la propriété sur l'objet.
    // Si la valeur n'existe pas, on retourne 'défaut'.
    return Reflect.get(obj, prop) ?? 'défaut';
  },

  // set() intercepte l'écriture d'une propriété.
  set(obj, prop, valeur) {
    // On affiche ce qui est modifié.
    console.log(`[SET] ${String(prop)} = ${valeur}`);

    // Reflect.set() écrit réellement la valeur dans l'objet.
    return Reflect.set(obj, prop, valeur);
  }
});

// Lecture de proxy.x.
// Cela déclenche le piège get().
console.log(proxy.x);
// Résultat : 1

// Écriture de proxy.y.
// Cela déclenche le piège set().
proxy.y = 42;

// Lecture d'une propriété qui n'existe pas.
// Le get retourne 'défaut'.
console.log(proxy.z);
// Résultat : défaut
Pourquoi Reflect ?

Reflect fournit des méthodes propres pour effectuer les opérations normales sur les objets. Dans un Proxy, il permet de ne pas réécrire soi-même le comportement standard.

Modules ES6

Les modules ES6 permettent de découper ton code en plusieurs fichiers. C’est essentiel pour organiser un projet proprement.

À quoi ça sert ?

Les modules permettent de séparer les responsabilités : un fichier pour les calculs, un fichier pour le DOM, un fichier pour l’API, un fichier pour le stockage, etc. Ton code devient plus clair et plus maintenable.

javascript

// FICHIER : math.js

// export permet de rendre une variable disponible
// pour les autres fichiers.
export const PI = 3.14159;

// Export nommé.
// On pourra importer cette fonction avec son nom exact : carre.
export function carre(x) {
  return x * x;
}

// Export par défaut.
// Un fichier ne peut avoir qu'un seul export default.
export default function cube(x) {
  return x ** 3;
}
javascript

// FICHIER : app.js

// Import de l'export default + imports nommés.
// cube vient de export default.
// PI et carre viennent des exports nommés.
import cube, { PI, carre } from './math.js';

// Utilisation de la fonction carre.
console.log(carre(4));
// Résultat : 16

// Utilisation de la fonction cube.
console.log(cube(4));
// Résultat : 64

// Utilisation de la constante PI.
console.log(PI);

// Import dynamique.
// Il permet de charger un module seulement quand on en a besoin.
const mod = await import('./math.js');

// Ici, mod contient les exports du fichier math.js.
console.log(mod.carre(5));
// Résultat : 25
Important :

Pour utiliser les modules dans le navigateur, ton script doit souvent être déclaré avec <script type="module">.

Optional chaining et nullish coalescing

L’optional chaining ?. permet d’accéder à une propriété sans faire planter le code si une valeur est null ou undefined.

Le nullish coalescing ?? permet de donner une valeur par défaut uniquement si la valeur de gauche est null ou undefined.

À quoi ça sert ?

Ces syntaxes sont très utiles quand tu manipules des données d’API, car certaines propriétés peuvent manquer. Elles évitent beaucoup d’erreurs du type : Cannot read properties of undefined.

javascript

// Exemple d'utilisateur.
// Parfois, adresse peut exister.
// Parfois, elle peut être absente.
const user = {
  prenom: 'Julien',
  adresse: {
    ville: 'Lyon'
  }
};

// Sans optional chaining, il faudrait vérifier chaque niveau.
// Avec ?. JavaScript s'arrête proprement si une partie est undefined ou null.
const ville = user?.adresse?.ville;

console.log(ville);
// Résultat : Lyon

// Si user.adresse n'existait pas,
// ville vaudrait undefined au lieu de provoquer une erreur.

// Optional chaining fonctionne aussi avec les tableaux.
const arr = ['JS', 'TS'];

// Récupère le premier élément si arr existe.
const first = arr?.[0];

console.log(first);
// Résultat : JS

// Optional chaining fonctionne aussi avec les méthodes.
const obj = {
  methode() {
    return 'Méthode appelée';
  }
};

// Appelle methode seulement si elle existe.
const result = obj.methode?.();

console.log(result);

// Nullish coalescing.
// ?? donne une valeur par défaut seulement si la valeur est null ou undefined.
const saisi = null;

const nom = saisi ?? 'Anonyme';

console.log(nom);
// Résultat : Anonyme

// Différence importante avec ||.
// 0 est une vraie valeur, même si elle est falsy.
const compte = 0 ?? 10;

console.log(compte);
// Résultat : 0

// Avec ||, le résultat aurait été 10,
// car 0 est considéré comme falsy.
const autreCompte = 0 || 10;

console.log(autreCompte);
// Résultat : 10
Différence entre ?? et || :

?? remplace seulement null et undefined. || remplace aussi les valeurs considérées comme fausses : 0, '', false, NaN.

// 08 — TYPESCRIPT

TypeScript — Bases & types

TypeScript est une surcouche de JavaScript qui ajoute un système de types. Cela permet de détecter beaucoup d’erreurs avant même d’exécuter le code.

À quoi ça sert ?

TypeScript aide à écrire du code plus fiable, plus lisible et plus facile à maintenir. Il est très utilisé dans les gros projets, notamment avec Angular, React, Node.js, les API, les applications métier et les projets professionnels.

Le navigateur ne comprend pas directement TypeScript. Le code TypeScript est donc compilé en JavaScript classique avant d’être exécuté.

Types primitifs

Les types primitifs permettent d’indiquer clairement le type de valeur attendu : texte, nombre, booléen, absence de valeur, etc.

typescript

// Type string.
// Une variable de type string contient du texte.
const prenom: string = 'Julien';

// Type number.
// TypeScript utilise number pour les nombres entiers et décimaux.
const age: number = 32;

// Type boolean.
// Un boolean vaut true ou false.
const actif: boolean = true;

// Type null.
// null représente une absence volontaire de valeur.
const rien: null = null;

// Type undefined.
// undefined signifie qu'une valeur n'est pas définie.
const pasDefini: undefined = undefined;

// Tableau de chaînes de caractères.
// Ici, tags ne peut contenir que des string.
const tags: string[] = ['js', 'ts'];

// Autre syntaxe pour écrire un tableau de nombres.
// Array<number> signifie tableau de number.
const ids: Array<number> = [1, 2, 3];

// Tuple.
// Un tuple est un tableau avec une taille et des types précis.
// Ici, point doit contenir exactement deux nombres.
const point: [number, number] = [10, 20];

// any désactive pratiquement les protections de TypeScript.
// La variable peut changer de type librement.
let nimporte: any = 42;

nimporte = 'string';

// unknown signifie : on ne connaît pas encore le type.
// Contrairement à any, TypeScript oblige à vérifier avant utilisation.
let donnee: unknown = getJson();

// On vérifie que donnee est bien une string avant d'utiliser toUpperCase().
if (typeof donnee === 'string') {
  donnee.toUpperCase();
}

// void signifie que la fonction ne retourne rien.
function log(msg: string): void {
  console.log(msg);
}

// never signifie que la fonction ne retourne jamais une valeur.
// Ici, elle interrompt le programme en lançant une erreur.
function erreur(msg: string): never {
  throw new Error(msg);
}
any vs unknown :

any retire les protections de TypeScript. unknown est plus sûr, car il oblige à vérifier le type avant d’utiliser la valeur.

Bonne pratique :

Évite any autant que possible. Si tu ne connais pas encore le type d’une donnée, préfère unknown, puis fais une vérification avec typeof, Array.isArray() ou une condition adaptée.

Inférence de type

TypeScript sait souvent deviner le type automatiquement. C’est ce qu’on appelle l’inférence de type.

typescript

// TypeScript comprend automatiquement que nom est une string.
const nom = 'Julien';

// TypeScript comprend automatiquement que prix est un number.
const prix = 19.99;

// TypeScript comprend automatiquement que connecte est un boolean.
const connecte = true;

// Ici, pas besoin d'écrire :
// const nom: string = 'Julien';
// TypeScript l'a déjà compris.

// Mais si une variable peut changer de type,
// il faut le préciser.
let id: number | string;

id = 123;
id = 'ABC-123';
Conseil :

Tu n’es pas obligé de typer toutes les variables simples. TypeScript peut souvent deviner. Par contre, il est très utile de typer les fonctions, les objets, les paramètres, les retours et les données venant d’une API.

Union types

Un union type permet d’autoriser plusieurs types ou plusieurs valeurs possibles. On utilise le symbole |.

typescript

// Cette variable peut contenir un number ou une string.
let identifiant: number | string;

identifiant = 10;
identifiant = 'user-10';

// Union de valeurs précises.
// Ici, statut ne peut avoir que ces trois valeurs.
type StatutCompte = 'actif' | 'pause' | 'archive';

let statut: StatutCompte = 'actif';

// Cette ligne serait refusée par TypeScript,
// car 'supprime' n'est pas dans les valeurs autorisées.
// statut = 'supprime';

// Fonction avec union type.
function afficherId(id: number | string): void {
  // Avant d'utiliser une méthode propre aux strings,
  // on vérifie le type.
  if (typeof id === 'string') {
    console.log(id.toUpperCase());
  } else {
    console.log(id.toFixed(0));
  }
}
À quoi ça sert ?

Les unions sont très utiles pour limiter les valeurs possibles. Par exemple : un statut, un rôle utilisateur, un état de formulaire, une catégorie ou une réponse API.

Interfaces vs types

Les interface et les type permettent de décrire la forme d’un objet. Ils rendent ton code plus clair et évitent les erreurs sur les propriétés.

typescript

// Une interface décrit la structure attendue d'un objet.
interface Utilisateur {
  // Propriété obligatoire de type number.
  id: number;

  // Propriété obligatoire de type string.
  prenom: string;

  // Propriété obligatoire de type string.
  email: string;

  // Le ? rend la propriété optionnelle.
  // Cela signifie que age peut être présent ou absent.
  age?: number;

  // readonly empêche de modifier la propriété après création.
  readonly creeLe: Date;
}

// Une interface peut hériter d'une autre interface avec extends.
// Admin contient toutes les propriétés de Utilisateur,
// plus la propriété permissions.
interface Admin extends Utilisateur {
  permissions: string[];
}

// Type basé sur une union de valeurs.
// Statut ne peut être que 'actif', 'pause' ou 'archive'.
type Statut = 'actif' | 'pause' | 'archive';

// Type tuple.
// Coords représente exactement deux nombres.
type Coords = [number, number];

// Type objet.
// Article contient un titre, un auteur et un statut.
type Article = {
  titre: string;
  auteur: Utilisateur;
  statut: Statut;
};
Interface ou type ?

Les deux sont très utilisés. En général, utilise interface pour décrire des objets ou des classes. Utilise type pour les unions, les tuples, les types composés ou les alias plus flexibles.

Utiliser une interface

Une fois l’interface créée, on peut l’utiliser pour typer un objet, un paramètre de fonction ou une réponse API.

typescript

// On crée un objet qui doit respecter l'interface Utilisateur.
const utilisateur: Utilisateur = {
  id: 1,
  prenom: 'Julien',
  email: 'julien@example.com',
  creeLe: new Date()
};

// age est optionnel, donc l'objet reste valide même sans age.

// Fonction qui reçoit obligatoirement un Utilisateur.
function afficherUtilisateur(user: Utilisateur): string {
  return `${user.prenom} — ${user.email}`;
}

console.log(afficherUtilisateur(utilisateur));

// Cette modification serait interdite,
// car creeLe est readonly.
// utilisateur.creeLe = new Date();

Fonctions typées

TypeScript permet de typer les paramètres d’une fonction et sa valeur de retour. C’est très utile pour éviter d’envoyer de mauvaises données à une fonction.

typescript

// Fonction avec deux paramètres number.
// Le : number après les parenthèses indique que la fonction retourne un number.
function additionner(a: number, b: number): number {
  return a + b;
}

// Fonction avec un paramètre optionnel par défaut.
// formel vaut false si aucune valeur n'est fournie.
function saluer(nom: string, formel: boolean = false): string {
  return formel ? `Bonjour ${nom}` : `Salut ${nom}`;
}

// Rest parameter typé.
// ...vals récupère tous les arguments dans un tableau de nombres.
function somme(...vals: number[]): number {
  return vals.reduce((a, b) => a + b, 0);
}

console.log(additionner(5, 3));
console.log(saluer('Julien'));
console.log(somme(1, 2, 3, 4));
À retenir :

Le typage des fonctions aide énormément à éviter les erreurs. Si une fonction attend deux nombres, TypeScript t’avertira si tu lui passes du texte ou une mauvaise structure.

Paramètres optionnels

On peut rendre un paramètre optionnel avec ?. Cela signifie qu’il peut être absent.

typescript

// Le paramètre ville est optionnel grâce au ?.
function presentation(prenom: string, ville?: string): string {
  // Si ville existe, on l'utilise.
  if (ville) {
    return `${prenom} habite à ${ville}`;
  }

  // Sinon, on retourne une phrase plus simple.
  return `${prenom}`;
}

console.log(presentation('Julien'));
console.log(presentation('Julien', 'Lyon'));
Attention :

Un paramètre optionnel peut valoir undefined. Il faut donc souvent vérifier son existence avant de l’utiliser.

Types de fonctions

On peut aussi créer un type qui décrit la signature d’une fonction : ses paramètres et son retour.

typescript

// Type de fonction.
// Comparator<T> représente une fonction qui compare deux valeurs du même type T
// et retourne un number.
type Comparator<T> = (a: T, b: T) => number;

// On crée une fonction de comparaison pour des Utilisateur.
const trierAge: Comparator<Utilisateur> = (a, b) => {
  // a.age ?? 0 signifie :
  // si a.age est null ou undefined, on utilise 0.
  return (a.age ?? 0) - (b.age ?? 0);
};

// Exemple d'utilisateurs.
const users: Utilisateur[] = [
  {
    id: 1,
    prenom: 'Julien',
    email: 'julien@example.com',
    age: 32,
    creeLe: new Date()
  },
  {
    id: 2,
    prenom: 'Emma',
    email: 'emma@example.com',
    age: 28,
    creeLe: new Date()
  }
];

// sort utilise la fonction trierAge.
users.sort(trierAge);

console.log(users);

Génériques simples

Les generics permettent de créer du code réutilisable tout en gardant les types. On les écrit souvent avec <T>.

À quoi ça sert ?

Un generic permet d’écrire une fonction qui fonctionne avec plusieurs types, sans perdre la sécurité de TypeScript.

typescript

// Fonction generic.
// T représente un type qui sera déterminé au moment de l'utilisation.
function retournerPremier<T>(tableau: T[]): T | undefined {
  return tableau[0];
}

// Ici, TypeScript comprend que T vaut string.
const premierTag = retournerPremier(['js', 'ts', 'angular']);

// Ici, TypeScript comprend que T vaut number.
const premierId = retournerPremier([1, 2, 3]);

console.log(premierTag);
console.log(premierId);
Pourquoi T | undefined ?

Si le tableau est vide, tableau[0] retourne undefined. TypeScript nous pousse donc à prévoir ce cas.

Typer une réponse API

TypeScript est très utile avec les API, car il permet de décrire la forme des données reçues.

typescript

// Interface représentant un article reçu depuis une API.
interface ArticleApi {
  id: number;
  titre: string;
  contenu: string;
  publie: boolean;
  tags: string[];
}

// Fonction qui récupère un article.
// Promise<ArticleApi> signifie que la fonction retourne une Promise
// qui donnera plus tard un ArticleApi.
async function getArticle(id: number): Promise<ArticleApi> {
  const reponse = await fetch(`/api/articles/${id}`);

  if (!reponse.ok) {
    throw new Error(`HTTP ${reponse.status}`);
  }

  const data = await reponse.json();

  // Ici, on indique à TypeScript que data correspond à ArticleApi.
  return data as ArticleApi;
}

// Exemple d'utilisation.
async function afficherArticle(): Promise<void> {
  const article = await getArticle(1);

  console.log(article.titre);
  console.log(article.tags);
}
Important :

TypeScript vérifie les types pendant le développement, mais il ne valide pas réellement les données au moment de l’exécution. Si une API renvoie une mauvaise structure, TypeScript ne peut pas toujours le voir automatiquement. Pour une validation runtime, il faut ajouter des vérifications ou utiliser une librairie spécialisée.

// 09 — TS AVANCÉ

TypeScript — Types avancés

Les types avancés de TypeScript permettent de créer du code plus flexible, plus robuste et plus réutilisable. Ils sont très utiles dans les projets professionnels, les frameworks comme Angular, les appels API typés, les composants réutilisables et les grosses applications.

À quoi ça sert ?

Ces notions permettent de mieux contrôler les formes de données, limiter les erreurs, créer des fonctions génériques, sécuriser les objets venant d’une API et écrire du code plus maintenable.

Generics

Les generics permettent d’écrire des fonctions, des classes ou des types réutilisables sans perdre l’information du type.

Idée simple :

Un generic, souvent écrit <T>, représente un type variable. TypeScript remplace ensuite T par le vrai type au moment où la fonction est utilisée.

typescript

// Fonction generic.
// T représente le type des éléments du tableau.
// Si on passe un tableau de number, T devient number.
// Si on passe un tableau de string, T devient string.
function premierType<T>(arr: T[]): T | undefined {
  // On retourne le premier élément du tableau.
  // Si le tableau est vide, arr[0] retourne undefined.
  return arr[0];
}

// Ici, TypeScript comprend que T vaut number.
// Donc n est de type number | undefined.
const n = premierType([1, 2]);

// Ici, TypeScript comprend que T vaut string.
// Donc s est de type string | undefined.
const s = premierType(['a', 'b']);

// Exemple d'utilisation.
console.log(n);
console.log(s);
Pourquoi utiliser un generic ici ?

Sans generic, on serait obligé d’écrire plusieurs fonctions : une pour les nombres, une pour les strings, une pour les objets, etc. Avec <T>, une seule fonction fonctionne avec plusieurs types.

Contraindre un generic avec extends

Parfois, on veut garder un type flexible, mais on veut quand même imposer une forme minimale. C’est là qu’on utilise extends.

typescript

// Ici, T est flexible,
// mais il doit obligatoirement avoir une propriété length de type number.
function longueur<T extends { length: number }>(item: T): number {
  // Comme TypeScript sait que item possède length,
  // on peut utiliser item.length sans erreur.
  return item.length;
}

// Une string possède length, donc c'est accepté.
longueur('abc');

// Un tableau possède length, donc c'est accepté.
longueur([1, 2]);

// Un objet peut aussi être accepté s'il possède length.
longueur({ length: 10, nom: 'test' });

// Cette ligne serait refusée,
// car un nombre ne possède pas de propriété length.
// longueur(123);
À quoi sert extends avec les generics ?

extends permet de dire : “je veux un type flexible, mais il doit au moins respecter cette structure”. C’est très pratique pour créer des fonctions réutilisables mais sécurisées.

Generics avec plusieurs types

Un generic peut utiliser plusieurs types variables. On peut donc écrire <A, B>, <T, U>, etc.

typescript

// Fonction avec deux generics.
// A représente le type du premier paramètre.
// B représente le type du deuxième paramètre.
function paire<A, B>(a: A, b: B): [A, B] {
  // On retourne un tuple contenant les deux valeurs.
  return [a, b];
}

// Ici, A vaut string et B vaut number.
const p1 = paire('age', 32);

// Ici, A vaut boolean et B vaut string.
const p2 = paire(true, 'connecté');

console.log(p1);
console.log(p2);

Union, intersection, literal types

TypeScript permet de combiner les types de plusieurs façons. Les plus importantes sont les unions, les intersections et les literal types.

  • Union : une valeur peut être de plusieurs types possibles.
  • Intersection : une valeur doit combiner plusieurs structures.
  • Literal type : une valeur est limitée à des textes ou nombres précis.
typescript

// Union type.
// Id peut être soit une string, soit un number.
type Id = string | number;

// Accepté : number.
const a: Id = 42;

// Accepté : string.
const b: Id = 'abc';

// Type représentant un objet qui possède un id.
type Identifiable = {
  id: number;
};

// Type représentant un objet qui possède un nom.
type Nommable = {
  nom: string;
};

// Intersection type.
// Entite doit avoir à la fois id ET nom.
type Entite = Identifiable & Nommable;

// Exemple valide.
const utilisateur: Entite = {
  id: 1,
  nom: 'Julien'
};

// Literal type.
// Direction ne peut contenir que ces quatre valeurs.
type Direction = 'haut' | 'bas' | 'gauche' | 'droite';

// La fonction accepte uniquement une Direction valide.
function deplacer(d: Direction): void {
  console.log(d);
}

deplacer('haut');

// Cette ligne serait refusée par TypeScript.
// deplacer('diagonale');
À retenir :

L’union utilise | et signifie “ou”. L’intersection utilise & et signifie “et”. Les literal types servent à limiter les valeurs possibles.

Type guards

Un type guard est une vérification qui permet à TypeScript de comprendre plus précisément le type d’une valeur.

À quoi ça sert ?

Les type guards sont très utiles quand une variable peut avoir plusieurs types. Ils permettent d’éviter les erreurs et d’utiliser les bonnes propriétés au bon moment.

typescript

// Fonction qui accepte soit une string, soit un number.
function format(val: string | number): string {
  // typeof permet de vérifier le type réel.
  if (typeof val === 'string') {
    // Dans ce bloc, TypeScript sait que val est une string.
    return val.toUpperCase();
  }

  // Ici, TypeScript sait que val est un number.
  return val.toFixed(2);
}

console.log(format('julien'));
console.log(format(12.345));

Type guard personnalisé

On peut aussi créer nos propres fonctions de vérification. C’est très utile avec des objets qui ont des formes différentes.

typescript

// Interface représentant un chien.
interface Chien {
  aboie: () => void;
}

// Interface représentant un chat.
interface Chat {
  miaule: () => void;
}

// Type guard personnalisé.
// animal is Chien indique à TypeScript :
// si cette fonction retourne true,
// alors animal doit être considéré comme un Chien.
function estChien(animal: Chien | Chat): animal is Chien {
  // On vérifie si la propriété aboie existe.
  return (animal as Chien).aboie !== undefined;
}

// Fonction qui reçoit soit un Chien, soit un Chat.
function interagir(a: Chien | Chat): void {
  if (estChien(a)) {
    // Grâce au type guard, TypeScript sait que a est un Chien.
    a.aboie();
  } else {
    // Sinon, TypeScript comprend que a est un Chat.
    a.miaule();
  }
}

// Exemple de chien.
const chien: Chien = {
  aboie: () => console.log('Wouf')
};

// Exemple de chat.
const chat: Chat = {
  miaule: () => console.log('Miaou')
};

interagir(chien);
interagir(chat);
Pourquoi écrire animal is Chien ?

Cette syntaxe ne sert pas seulement à retourner un booléen. Elle informe TypeScript du type exact quand la condition est vraie.

Enums vs union de littéraux

Les enum permettent de regrouper des valeurs nommées. Mais dans beaucoup de projets modernes, on préfère parfois utiliser un objet avec as const et une union de littéraux.

typescript

// Enum classique TypeScript.
// Il permet de regrouper plusieurs valeurs possibles.
enum RoleEnum {
  User = 'user',
  Admin = 'admin',
  Guest = 'guest'
}

// Utilisation d'un enum.
const roleEnum: RoleEnum = RoleEnum.Admin;

console.log(roleEnum);
typescript

// Alternative moderne avec un objet constant.
const Role = {
  User: 'user',
  Admin: 'admin',
  Guest: 'guest'
} as const;

// as const dit à TypeScript :
// garde les valeurs exactes 'user', 'admin', 'guest',
// au lieu de les élargir en simple string.

// typeof Role récupère le type de l'objet Role.
// keyof typeof Role récupère ses clés : 'User' | 'Admin' | 'Guest'.
// typeof Role[keyof typeof Role] récupère ses valeurs : 'user' | 'admin' | 'guest'.
type Role = typeof Role[keyof typeof Role];

// role ne peut contenir que 'user', 'admin' ou 'guest'.
const role: Role = Role.Admin;

console.log(role);
Enum ou union ?

Les enum restent utiles, surtout dans certains projets Angular. L’approche as const + union est souvent appréciée car elle est légère, proche du JavaScript et très stricte côté TypeScript.

Classes typées

TypeScript permet de typer les classes JavaScript : propriétés, constructeur, méthodes, visibilité et interfaces.

À quoi ça sert ?

Les classes typées sont utiles pour créer des modèles solides : utilisateur, produit, recette, tâche, dépense, service API, composant, etc.

typescript

// Interface qui impose une propriété id.
interface Identifiable {
  id: number;
}

// La classe Personne doit respecter l'interface Identifiable.
// Donc elle doit forcément posséder une propriété id de type number.
class Personne implements Identifiable {
  // Syntaxe courte dans le constructor.
  // public id crée automatiquement une propriété publique id.
  // private _mdp crée une propriété privée.
  // readonly nom crée une propriété lisible mais non modifiable après création.
  constructor(
    public id: number,
    private _mdp: string,
    readonly nom: string
  ) {}

  // Méthode qui reçoit une string et retourne un boolean.
  verifierMdp(saisie: string): boolean {
    return saisie === this._mdp;
  }
}

// Création d'une instance.
const personne = new Personne(1, 'secret', 'Julien');

// id est public, donc accessible.
console.log(personne.id);

// nom est readonly, donc lisible.
console.log(personne.nom);

// Cette ligne serait refusée,
// car nom est readonly.
// personne.nom = 'Autre nom';

// Cette ligne serait refusée,
// car _mdp est private.
// console.log(personne._mdp);

// On peut vérifier le mot de passe via la méthode publique.
console.log(personne.verifierMdp('secret'));
public, private, readonly :

public signifie accessible depuis l’extérieur. private signifie accessible seulement dans la classe. readonly signifie que la propriété ne peut plus être modifiée après initialisation.

Types utilitaires simples

TypeScript propose des types utilitaires intégrés pour transformer rapidement des types existants.

typescript

// Type de base.
interface Produit {
  id: number;
  nom: string;
  prix: number;
  stock: number;
}

// Partial rend toutes les propriétés optionnelles.
// Utile pour modifier seulement une partie d'un objet.
type ProduitPatch = Partial<Produit>;

// Pick garde seulement certaines propriétés.
type ProduitResume = Pick<Produit, 'id' | 'nom'>;

// Omit retire certaines propriétés.
type ProduitSansStock = Omit<Produit, 'stock'>;

// Readonly rend toutes les propriétés non modifiables.
type ProduitLectureSeule = Readonly<Produit>;

// Exemple de patch : on modifie seulement le prix.
const patch: ProduitPatch = {
  prix: 29.99
};

// Exemple de résumé.
const resume: ProduitResume = {
  id: 1,
  nom: 'Clavier'
};
Pourquoi les utility types sont utiles ?

Ils évitent de réécrire plusieurs variantes d’un même type. Par exemple, tu peux avoir un type complet pour un produit, puis un type partiel pour une modification avec PATCH.

// 10 — TS ASYNC

TypeScript — Promises & API typées

TypeScript permet de typer précisément le code asynchrone : les Promise, les fonctions async, les réponses API, les tableaux reçus depuis un serveur et les erreurs possibles.

À quoi ça sert ?

Quand tu fais une requête API avec fetch(), JavaScript récupère des données dont la structure peut être complexe. TypeScript permet de décrire cette structure pour éviter les erreurs comme accéder à une propriété qui n’existe pas.

Une fonction async retourne toujours une Promise. Avec TypeScript, on peut préciser ce que cette Promise contiendra une fois résolue : Promise<number>, Promise<string>, Promise<Article>, etc.

Promises génériques

Une Promise<T> signifie : “cette Promise donnera plus tard une valeur de type T”.

typescript

// Cette fonction attend un certain nombre de millisecondes.
// Elle ne retourne aucune donnée utile.
// C'est pour cela qu'on écrit Promise<void>.
function attendre(ms: number): Promise<void> {
  // On retourne une nouvelle Promise.
  return new Promise((resolve) => {
    // setTimeout exécute resolve après le délai demandé.
    // Quand resolve est appelé, la Promise est terminée.
    setTimeout(resolve, ms);
  });
}

// Fonction async qui retourne une Promise contenant un number.
// Même si on écrit return 42, TypeScript comprend que la fonction
// retourne en réalité Promise<number> car elle est async.
async function getNombre(): Promise<number> {
  // await attend que la Promise attendre(100) soit terminée.
  await attendre(100);

  // Cette valeur sera emballée automatiquement dans une Promise.
  return 42;
}

// Fonction async qui retourne une Promise contenant une string.
async function salutation(): Promise<string> {
  return 'Bonjour';
}

// Exemple d'utilisation.
async function demoPromisesTypees(): Promise<void> {
  // nombre est de type number.
  const nombre = await getNombre();

  // message est de type string.
  const message = await salutation();

  console.log(nombre);
  console.log(message);
}

demoPromisesTypees();
À retenir :

Promise<void> signifie que l’opération est asynchrone mais ne renvoie pas de valeur utile. Promise<number> signifie que la Promise donnera un nombre. Promise<string> signifie qu’elle donnera une chaîne de caractères.

Fetch typé

Avec fetch(), TypeScript ne connaît pas automatiquement la forme des données JSON reçues. On peut donc créer une interface pour décrire la réponse attendue.

Exemple concret :

Si ton API renvoie un article avec un id, un titre, un contenu, un auteur et des tags, tu peux décrire cette structure avec une interface TypeScript.

typescript

// Interface qui décrit la structure d'un article reçu depuis l'API.
interface Article {
  // Identifiant unique de l'article.
  id: number;

  // Titre de l'article.
  titre: string;

  // Contenu principal de l'article.
  contenu: string;

  // Objet imbriqué représentant l'auteur.
  auteur: {
    id: number;
    nom: string;
  };

  // Tableau de tags.
  tags: string[];
}

// Fonction générique pour faire un GET typé.
// T représente le type de donnée que l'on attend en réponse.
async function apiGet<T>(url: string): Promise<T> {
  // fetch retourne une Promise contenant une Response.
  const reponse = await fetch(url);

  // fetch ne déclenche pas automatiquement une erreur
  // pour les statuts HTTP comme 404 ou 500.
  // On vérifie donc reponse.ok manuellement.
  if (!reponse.ok) {
    throw new Error(`HTTP ${reponse.status}`);
  }

  // reponse.json() transforme le JSON reçu en objet JavaScript.
  const data = await reponse.json();

  // Ici, on dit à TypeScript :
  // considère que data est de type T.
  // Attention : cela ne valide pas réellement les données au runtime.
  return data as T;
}
Attention :

as T donne une indication à TypeScript, mais ne vérifie pas réellement les données pendant l’exécution. Si l’API renvoie une mauvaise structure, TypeScript ne le verra pas automatiquement.

Utiliser apiGet avec un objet

Ici, on indique à apiGet<Article> que l’on attend un seul article. TypeScript pourra ensuite proposer l’autocomplétion sur titre, auteur.nom, tags, etc.

typescript

// Fonction async car on utilise await à l'intérieur.
async function chargerArticle(): Promise<void> {
  try {
    // On indique que l'API doit retourner un Article.
    const art = await apiGet<Article>('/api/articles/1');

    // TypeScript sait que art possède une propriété titre.
    console.log(art.titre);

    // TypeScript sait aussi que auteur est un objet
    // contenant une propriété nom.
    console.log(art.auteur.nom);

    // TypeScript sait que tags est un tableau de string.
    art.tags.forEach((tag) => {
      console.log(tag.toUpperCase());
    });
  } catch (err) {
    // En TypeScript moderne, err est souvent de type unknown.
    // Il faut donc vérifier avant d'utiliser err.message.
    if (err instanceof Error) {
      console.error(err.message);
    } else {
      console.error('Erreur inconnue', err);
    }
  }
}

Utiliser apiGet avec un tableau

Si l’API retourne une liste d’articles, on utilise Article[]. Cela signifie : tableau contenant uniquement des objets de type Article.

// Fonction qui charge plusieurs articles.

  const liste = await apiGet<Article[]>('/api/articles');

  // TypeScript sait que liste est un tableau.
  // Il sait aussi que chaque élément est un Article.
  const titres = liste.map((a) => a.titre);

  console.log(titres);

    console.log(`${article.auteur.nom} — ${article.titre}`);
  });
}

Quand l’API est typée, TypeScript t’aide à éviter les fautes de propriété. Par exemple, si tu écris article.titree au lieu de article.titre, TypeScript peut te prévenir avant l’exécution.

Promise.all typé

Promise.all() permet de lancer plusieurs Promises en parallèle. Avec TypeScript, chaque résultat peut garder son propre type.

Exemple concret :

Pour charger un dashboard, tu peux récupérer en même temps : l’utilisateur, ses articles et ses statistiques. Ces trois données sont différentes, mais TypeScript peut conserver leur type exact.

typescript

// Interface représentant un utilisateur.
interface Utilisateur {
  id: number;
  prenom: string;
  email: string;
}

// Interface représentant des statistiques.
interface StatsUtilisateur {
  vues: number;
  likes: number;
}

// Fonction qui charge toutes les données du dashboard.
async function chargerDashboard(userId: number): Promise<{
  user: Utilisateur;
  articles: Article[];
  stats: StatsUtilisateur;
}> {
  // Promise.all lance les trois requêtes en même temps.
  // Chaque apiGet possède son propre type.
  const [user, articles, stats] = await Promise.all([
    apiGet<Utilisateur>(`/users/${userId}`),
    apiGet<Article[]>(`/users/${userId}/articles`),
    apiGet<StatsUtilisateur>(`/users/${userId}/stats`)
  ]);

  // TypeScript sait que :
  // user est un Utilisateur
  // articles est un Article[]
  // stats est un StatsUtilisateur
  return {
    user,
    articles,
    stats
  };
}

// Exemple d'utilisation.
async function afficherDashboard(): Promise<void> {
  const dashboard = await chargerDashboard(1);

  console.log(dashboard.user.prenom);
  console.log(dashboard.articles.length);
  console.log(dashboard.stats.vues);
}

afficherDashboard();
Pourquoi Promise.all ici ?

Les trois requêtes ne dépendent pas forcément les unes des autres. On peut donc les lancer en parallèle pour gagner du temps au lieu de les attendre une par une.

Promise.allSettled typé

Promise.allSettled() est utile quand tu veux récupérer les résultats possibles, même si certaines requêtes échouent.

typescript

// Fonction qui charge plusieurs ressources,
// mais accepte que certaines échouent.
async function chargerDashboardTolérant(userId: number): Promise<void> {
  const resultats = await Promise.allSettled([
    apiGet<Utilisateur>(`/users/${userId}`),
    apiGet<Article[]>(`/users/${userId}/articles`),
    apiGet<StatsUtilisateur>(`/users/${userId}/stats`)
  ]);

  resultats.forEach((resultat) => {
    // Si status vaut fulfilled, la Promise a réussi.
    if (resultat.status === 'fulfilled') {
      console.log('Succès :', resultat.value);
    } else {
      // Si status vaut rejected, la Promise a échoué.
      console.error('Erreur :', resultat.reason);
    }
  });
}

Quand utiliser allSettled ?

Utilise Promise.allSettled() pour un dashboard ou une interface qui peut afficher une partie des données même si une requête échoue.

Typer les erreurs

En TypeScript, il est plus prudent de considérer les erreurs comme inconnues, puis de vérifier leur type avant de les utiliser.

typescript

// Fonction utilitaire pour transformer une erreur inconnue en message lisible.
function getMessageErreur(err: unknown): string {
  // Si err est une vraie instance de Error,
  // on peut utiliser err.message.
  if (err instanceof Error) {
    return err.message;
  }

  // Si err est une string, on la retourne directement.
  if (typeof err === 'string') {
    return err;
  }

  // Sinon, on retourne un message générique.
  return 'Erreur inconnue';
}

async function exempleErreur(): Promise<void> {
  try {
    const article = await apiGet<Article>('/api/articles/999');

    console.log(article);
  } catch (err) {
    console.error(getMessageErreur(err));
  }
}

Validation simple des données API

Le typage TypeScript aide pendant le développement, mais il ne remplace pas une vraie validation des données reçues depuis une API.

typescript

// Type guard simple pour vérifier qu'une donnée ressemble à un Article.
function estArticle(data: unknown): data is Article {
  // On vérifie que data est bien un objet non null.
  if (typeof data !== 'object' || data === null) {
    return false;
  }

  // On crée une version indexable de data.
  const obj = data as Record<string, unknown>;

  // On vérifie les propriétés principales.
  return (
    typeof obj.id === 'number' &&
    typeof obj.titre === 'string' &&
    typeof obj.contenu === 'string' &&
    Array.isArray(obj.tags)
  );
}

// Fonction plus prudente pour charger un article.
async function getArticleValide(id: number): Promise<Article> {
  const data = await apiGet<unknown>(`/api/articles/${id}`);

  // Même si l'API répond, on vérifie la structure.
  if (!estArticle(data)) {
    throw new Error('Structure Article invalide');
  }

  // Grâce au type guard, TypeScript sait maintenant que data est un Article.
  return data;
}
Important :

Le type donné à apiGet<T> est une promesse faite à TypeScript. Il faut quand même valider les données API en production, surtout si les données viennent d’un serveur externe, d’un utilisateur ou d’une source non maîtrisée.

TypeScript — Utility types

Les utility types sont des types fournis directement par TypeScript. Ils permettent de transformer un type existant pour en créer un nouveau, sans devoir tout réécrire.

À quoi ça sert ?

Les utility types évitent la duplication. Par exemple, si tu as déjà un type Article, tu peux créer automatiquement un type pour modifier un article, créer un article sans id, afficher seulement un aperçu, rendre les propriétés en lecture seule, etc.

Ils sont très utilisés dans les projets professionnels, les API typées, Angular, les formulaires, les services, les DTO, les composants et les architectures propres.

Tableau des utility types principaux

Utility Effet Usage
Partial<T> Toutes les propriétés deviennent optionnelles. Patch / mise à jour partielle.
Required<T> Toutes les propriétés deviennent obligatoires. Normalisation / validation.
Readonly<T> Toutes les propriétés deviennent en lecture seule. Éviter les mutations.
Pick<T, K> Garde seulement certaines clés. Aperçu, résumé, carte, liste.
Omit<T, K> Retire certaines clés. Création sans ID, nettoyage de données.
Record<K, V> Crée un objet dictionnaire typé. Tables de mapping, traductions, rôles.
Awaited<T> Récupère le type résolu d’une Promise. Retour de fonction async.
ReturnType<F> Récupère le type de retour d’une fonction. Réutiliser un retour sans duplication.

Type de base utilisé dans les exemples

Pour comprendre les utility types, on part d’une interface simple : un article avec un id, un titre, un contenu et un état de publication.

Omit<T, K>

Omit<T, K> crée un nouveau type en retirant une ou plusieurs propriétés. C’est très utile quand certaines données sont générées par le serveur.

Exemple concret :

Quand tu crées un nouvel article, tu n’as souvent pas encore d’id. L’id est généralement créé par la base de données ou le serveur.

// Elle reçoit un article sans id,
// puis retourne une Promise contenant un Article complet.

Transitions CSS expliquées

Une transition CSS sert à rendre un changement visuel progressif. Sans transition, un bouton change instantanément de couleur, de taille ou de position. Avec une transition, le navigateur anime doucement le passage entre l’état normal et l’état modifié.

À quoi ça sert ?

Les transitions rendent une interface plus agréable et plus moderne. Elles sont très utilisées sur les boutons, les cartes, les menus, les modales, les liens, les effets de survol, les sidebars, les formulaires ou les animations d’apparition.

À retenir :

Utilise en priorité transform et opacity, car ces propriétés sont généralement plus performantes que width, height, top ou left. Elles évitent souvent de recalculer toute la mise en page.

La propriété transition

transition indique au navigateur quelles propriétés doivent être animées, combien de temps l’animation dure, avec quelle courbe de vitesse, et éventuellement avec quel délai.

css

.bouton {
  /*
    transition-property indique quelles propriétés CSS seront animées.

    Ici, on demande au navigateur d'animer :
    - background : le changement de couleur de fond
    - transform : les changements comme scale(), rotate(), translate(), etc.
  */
  transition-property: background, transform;

  /*
    transition-duration indique la durée de la transition.

    0.3s signifie 0,3 seconde.
    Plus la durée est grande, plus l'animation est lente.
  */
  transition-duration: 0.3s;

  /*
    transition-timing-function contrôle la courbe de vitesse.

    ease-out signifie :
    - départ rapide
    - ralentissement à la fin

    C'est très agréable pour les boutons et les cartes.
  */
  transition-timing-function: ease-out;

  /*
    transition-delay ajoute un délai avant le début de la transition.

    0s signifie qu'il n'y a aucun délai.
  */
  transition-delay: 0s;
}

.bouton {
  /*
    Version raccourcie.

    Syntaxe :
    transition: propriété durée timing-function délai;

    Ici, on anime background et transform avec la même durée.
  */
  transition: background 0.3s ease-out, transform 0.3s ease-out;
}

.bouton:hover {
  /*
    Au survol, les valeurs changent.

    Comme background et transform sont déclarés dans transition,
    le navigateur anime le passage entre l'état normal et l'état hover.
  */
  background: cyan;
  transform: translateY(-3px);
}

.carte {
  /*
    On peut animer plusieurs propriétés avec des durées différentes.

    background dure 0.4s.
    transform dure 0.5s avec une courbe personnalisée.
    box-shadow dure 0.6s et commence après un délai de 0.1s.
  */
  transition:
    background 0.4s ease,
    transform 0.5s cubic-bezier(0.25, 1, 0.5, 1),
    box-shadow 0.6s ease 0.1s;
}
Erreur fréquente :

Écrire une transition ne suffit pas. Il faut aussi qu’une propriété change réellement entre l’état normal et l’état modifié, par exemple avec :hover, une classe .active, ou une modification faite en JavaScript.

Timing functions

La timing function contrôle la sensation du mouvement : linéaire, accéléré, ralenti ou avec un effet plus marqué.

Nom Comportement Usage

ease Démarre normalement puis ralentit. Effet général simple.
ease-in Démarre lentement puis accélère. Sortie d’un élément.

Keyframes

Une transition anime un passage simple entre deux états. Une animation @keyframes permet de définir plusieurs étapes et peut tourner en boucle.

Différence simple :

Une transition réagit à un changement d’état. Une animation keyframes peut jouer automatiquement, en boucle, ou suivre plusieurs étapes définies.

css

@keyframes pulse-glow {
  /*
    0% représente le début de l'animation.
    100% représente la fin.

    Ici, on groupe 0% et 100% car on veut le même état
    au début et à la fin de l'animation.
  */
  0%,
  100% {
    /*
      box-shadow crée une lueur autour de l'élément.

      Ici, le glow est petit et visible.
    */
    box-shadow: 0 0 0 0 rgba(0, 240, 255, 0.4);
  }

  /*
    50% représente le milieu de l'animation.
  */
  50% {
    /*
      Le glow s'étend jusqu'à 14px,
      puis devient transparent.
    */
    box-shadow: 0 0 0 14px rgba(0, 240, 255, 0);
  }

.bouton-pulse {

    animation applique les keyframes à l'élément.

    animation: nom durée courbe répétition;

    2s : durée d'un cycle
    ease-in-out : accélération douce
    infinite : répétition infinie

  animation: pulse-glow 2s ease-in-out infinite;

Transform

transform permet de déplacer, agrandir, tourner ou déformer un élément sans recalculer toute la mise en page. C’est pour cela qu’on l’utilise souvent dans les animations modernes.

css

.demo {
  /*
    translateX(20px) déplace l'élément sur l'axe horizontal X.

    Valeur positive : vers la droite.
    Valeur négative : vers la gauche.
  */
  transform: translateX(20px);

  /*
    translate(10px, -5px) déplace l'élément sur deux axes :

    10px sur X : vers la droite
    -5px sur Y : vers le haut
  */
  transform: translate(10px, -5px);

  /*
    rotate(15deg) fait tourner l'élément de 15 degrés.
  */
  transform: rotate(15deg);

  /*
    scale(1.1) agrandit l'élément à 110% de sa taille.

    scale(1) = taille normale.
    scale(0.9) = plus petit.
    scale(1.1) = plus grand.
  */
  transform: scale(1.1);

  /*
    skewX(-10deg) déforme l'élément sur l'axe X.
  */
  transform: skewX(-10deg);

  /*
    Plusieurs transformations peuvent être combinées.

    L'ordre compte :
    le navigateur applique les transformations dans l'ordre écrit.
  */
  transform: translateY(-4px) scale(1.05) rotate(-2deg);
}

  /*
    perspective donne une profondeur 3D aux enfants transformés.

    Plus la valeur est petite, plus l'effet 3D est fort.
  */
  perspective: 1000px;
}

  /*
    rotateY(45deg) fait tourner l'élément sur l'axe vertical.
    translateZ(50px) déplace l'élément dans la profondeur.

  transform: rotateY(45deg) translateZ(50px);

    will-change indique au navigateur qu'une propriété va bientôt changer.

    Ici, on prévient que transform va être animé.

    Trop de will-change peut consommer inutilement de la mémoire.

  will-change: transform;

Animations et transitions pilotées par JavaScript

JavaScript ne doit pas forcément calculer toute l’animation. Très souvent, son rôle est simplement de déclencher un changement d’état : ajouter une classe, retirer une classe, écouter la fin d’une transition, ou lancer une animation contrôlée.

À retenir :

Dans une interface moderne, le meilleur réflexe est souvent de laisser le CSS gérer l’apparence et les transitions, puis d’utiliser JavaScript seulement pour déclencher l’état : ouvrir un menu, afficher une modale, révéler une section, lancer un compteur, etc.

Toggle de classe

C’est la méthode la plus simple et la plus propre : CSS gère le style, JavaScript gère l’interaction utilisateur.

Principe :

L’élément a un état normal en CSS. Quand l’utilisateur clique, JavaScript ajoute une classe comme .open, .active ou .visible. Le CSS détecte cette classe et lance la transition.

javascript

// On récupère le menu dans le DOM grâce à son id.
// document.getElementById('menu') cherche un élément qui possède id="menu".
const menu = document.getElementById('menu');

// On récupère le bouton burger.
// Ce bouton servira à ouvrir ou fermer le menu.
const burger = document.getElementById('burger');

// On écoute le clic sur le bouton burger.
burger.addEventListener('click', () => {
  /*
    classList.toggle('open') fonctionne comme un interrupteur.

    Si la classe open n'existe pas :
    - JavaScript l'ajoute.

    Si la classe open existe déjà :
    - JavaScript la retire.

    Le CSS peut ensuite changer l'apparence du menu grâce à .menu.open.
  */
  menu.classList.toggle('open');
});

CSS associé au toggle

Le CSS définit l’état fermé du menu et son état ouvert. La transition permet de passer progressivement d’un état à l’autre.

css

.menu {
  /*
    État fermé du menu.

    translateX(-100%) déplace le menu complètement vers la gauche.
    Il sort donc de l'écran.
  */
  transform: translateX(-100%);

  /*
    transition rend l'ouverture et la fermeture fluides.

    Ici, on anime transform pendant 0.3 seconde
    avec une courbe ease.
  */
  transition: transform 0.3s ease;
}

.menu.open {
  /*
    État ouvert du menu.

    Quand JavaScript ajoute la classe .open,
    le menu revient à sa position normale.
  */
  transform: translateX(0);
}
Pourquoi c’est une bonne méthode ?

Le code reste bien séparé : le CSS s’occupe du visuel, JavaScript s’occupe seulement de l’interaction. C’est plus propre, plus maintenable et plus facile à déboguer.

Version plus sécurisée du toggle

Dans un vrai projet, il est préférable de vérifier que les éléments existent avant d’ajouter les événements. Cela évite les erreurs si le script est chargé sur une page qui ne contient pas le menu.

javascript

// On récupère les éléments.

const boutonBurger = document.getElementById('burger');

// On vérifie que les deux éléments existent.
if (menuMobile && boutonBurger) {
  boutonBurger.addEventListener('click', () => {
    // On ouvre ou ferme le menu.
    menuMobile.classList.toggle('open');

    /*
      Bonus accessibilité :
      aria-expanded indique aux lecteurs d'écran si le menu est ouvert ou fermé.
    */
    const isOpen = menuMobile.classList.contains('open');

    boutonBurger.setAttribute('aria-expanded', String(isOpen));
  });
}

IntersectionObserver

IntersectionObserver sert à détecter quand un élément entre dans la zone visible de l’écran. C’est très utile pour révéler des sections au scroll sans écouter l’événement scroll en permanence.

À quoi ça sert ?

Tu peux l’utiliser pour faire apparaître des cartes au scroll, animer des sections, charger des images seulement quand elles deviennent visibles, ou déclencher un compteur quand une statistique arrive à l’écran.

javascript

/*
  IntersectionObserver observe un ou plusieurs éléments.

  Quand un élément entre ou sort de la zone visible,
  le callback est exécuté.
*/
const observer = new IntersectionObserver((entries) => {
  /*
    entries est un tableau.

    Il contient les éléments observés
    et leur état de visibilité.
  */
  entries.forEach((entry) => {
    /*
      entry.isIntersecting vaut true si l'élément est visible
      dans le viewport.
    */
    if (entry.isIntersecting) {
      /*
        On ajoute une classe CSS pour lancer l'animation d'apparition.

        Exemple :
        .chapter {
          opacity: 0;
          transform: translateY(30px);
          transition: opacity 0.5s ease, transform 0.5s ease;
        }

        .chapter.is-visible {
          opacity: 1;
          transform: translateY(0);
        }
      */
      entry.target.classList.add('is-visible');

      /*
        On arrête d'observer cet élément.

        Cela évite du travail inutile,
        surtout si l'animation ne doit se jouer qu'une seule fois.
      */
      observer.unobserve(entry.target);
    }
  });
}, {
  /*
    threshold indique le pourcentage visible nécessaire
    pour déclencher le callback.

    0.15 signifie : déclenche quand 15% de l'élément est visible.
  */
  threshold: 0.15,

  /*
    rootMargin permet de modifier virtuellement la zone d'observation.

    Ici, -10% en bas signifie que l'effet se déclenche un peu
    avant que l'élément soit trop bas dans l'écran.
  */
  rootMargin: '0px 0px -10% 0px'
});

// On sélectionne toutes les sections du cours.
document.querySelectorAll('.chapter').forEach((el) => {
  // Chaque section est donnée à l'observer.
  observer.observe(el);
});

requestAnimationFrame

requestAnimationFrame demande au navigateur d’exécuter une fonction au bon moment pour une animation. C’est mieux que setInterval pour animer, car le navigateur synchronise avec le rendu de l’écran.

À quoi ça sert ?

Utilise requestAnimationFrame quand JavaScript doit calculer une valeur à chaque frame : compteur animé, barre de progression, canvas, animation personnalisée, déplacement contrôlé, etc.

javascript

// Fonction qui anime un compteur de 0 jusqu'à une valeur cible.
function animerCompteur(el, cible, duration = 1500) {
  /*
    performance.now() donne un temps très précis en millisecondes.

    On l'utilise pour connaître le moment exact du début de l'animation.
  */
  const debut = performance.now();

  /*
    tick est la fonction appelée à chaque frame.

    Le navigateur lui passe automatiquement le temps actuel
    dans le paramètre now.
  */
  function tick(now) {
    /*
      On calcule la progression de l'animation.

      now - debut = temps écoulé depuis le début.
      On divise par duration pour obtenir une valeur entre 0 et 1.

      Math.min(..., 1) évite de dépasser 1.
    */
    const progres = Math.min((now - debut) / duration, 1);

    /*
      Courbe ease-out maison.

      L'animation part vite puis ralentit à la fin.
      Cela paraît plus naturel qu'une progression linéaire.
    */
    const ease = 1 - Math.pow(1 - progres, 3);

    /*
      On calcule la valeur actuelle du compteur.

      cible * ease donne une valeur progressive entre 0 et la cible.
      Math.round arrondit pour afficher un entier.
    */
    el.textContent = Math.round(cible * ease);

    /*
      Tant que la progression est inférieure à 1,
      l'animation n'est pas terminée.

      On demande donc une nouvelle frame au navigateur.
    */
    if (progres < 1) {
      requestAnimationFrame(tick);
    }
  }

  /*
    Lance la première frame.

    Ensuite, tick se rappellera lui-même avec requestAnimationFrame
    jusqu'à la fin de l'animation.
  */
  requestAnimationFrame(tick);
}

// Exemple d'utilisation.
const compteur = document.getElementById('compteur');

if (compteur) {
  animerCompteur(compteur, 9999);
}
Pourquoi pas setInterval ?

setInterval exécute une fonction à intervalle fixe, sans être parfaitement synchronisé avec le rendu visuel. requestAnimationFrame est pensé pour les animations : il laisse le navigateur choisir le meilleur moment pour dessiner.

Web Animations API

La Web Animations API permet de créer une animation directement en JavaScript avec plusieurs étapes, puis de la contrôler : pause, play, reverse, cancel, finish, etc.

Quand l’utiliser ?

Utilise-la quand tu veux contrôler une animation avec JavaScript sans écrire forcément de @keyframes en CSS, ou quand tu veux mettre en pause, relancer, inverser ou annuler une animation dynamiquement.

javascript

// Élément que l'on veut animer.
const el = document.querySelector('.cible');

if (el) {
  /*
    animate() reçoit deux paramètres :

    1. Un tableau d'étapes, un peu comme des keyframes.
    2. Un objet d'options : durée, easing, répétitions, etc.
  */
  const anim = el.animate([
    /*
      Étape 1 : état initial.

      L'élément est à sa position normale,
      avec une taille normale et une opacité complète.
    */
    {
      transform: 'translateY(0) scale(1)',
      opacity: 1
    },

    /*
      Étape 2 : état intermédiaire.

      L'élément monte légèrement,
      grossit un peu,
      et devient légèrement transparent.
    */
    {
      transform: 'translateY(-20px) scale(1.1)',
      opacity: 0.8
    },

    /*
      Étape 3 : retour à l'état initial.
    */
    {
      transform: 'translateY(0) scale(1)',
      opacity: 1
    }
  ], {
    /*
      Durée totale de l'animation en millisecondes.
      800 = 0,8 seconde.
    */
    duration: 800,

    /*
      Courbe de vitesse.
      cubic-bezier permet une animation plus personnalisée.
    */
    easing: 'cubic-bezier(0.25, 1, 0.5, 1)',

    /*
      Nombre de répétitions.
      Ici, l'animation se joue deux fois.
    */
    iterations: 2
  });

  /*
    pause() met l'animation en pause.
  */
  anim.pause();

  /*
    play() lance ou reprend l'animation.
  */
  anim.play();

  /*
    reverse() inverse le sens de lecture de l'animation.
  */
  anim.reverse();

  /*
    onfinish est appelé quand l'animation est terminée.
  */
  anim.onfinish = () => {
    console.log('Animation terminée !');
  };
}

transitionend et animationend

Ces événements permettent de savoir précisément quand une transition ou une animation CSS est terminée. C’est très pratique pour supprimer un élément après son animation de sortie ou enchaîner une action.

javascript

// Exemple : on récupère un panneau à fermer.
const panneau = document.querySelector('.panneau');

if (panneau) {
  panneau.addEventListener('transitionend', (event) => {
    /*
      transitionend peut se déclencher pour plusieurs propriétés.

      Exemple :
      - opacity
      - transform
      - background
      - box-shadow

      On vérifie donc que c'est bien transform qui vient de finir.
    */
    if (event.propertyName === 'transform') {
      /*
        On supprime le panneau seulement après la fin de la transition.

        Cela évite de retirer l'élément brutalement avant la fin visuelle.
      */
      panneau.remove();
    }
  });
}

// Exemple : écouter la fin d'une animation CSS @keyframes.
const elementAnime = document.querySelector('.element-anime');

if (elementAnime) {
  elementAnime.addEventListener('animationend', () => {
    /*
      Ce callback est exécuté quand l'animation CSS est terminée.
    */
    console.log('Animation terminée');
  });
}
Petit piège :

transitionend peut se déclencher plusieurs fois si plusieurs propriétés sont animées. C’est pour ça qu’on vérifie souvent event.propertyName.

// 14 — EVENT LOOP

Event loop, microtasks et macrotasks

L’event loop est le mécanisme qui organise l’exécution du JavaScript. Elle décide quand exécuter le code synchrone, les callbacks, les timers, les Promises, les événements utilisateur et le rendu du navigateur.

À quoi ça sert ?

Comprendre l’event loop permet de mieux comprendre pourquoi certaines lignes de code ne s’exécutent pas dans l’ordre où elles sont écrites. C’est essentiel pour maîtriser setTimeout, Promise, async/await, fetch et les animations JavaScript.

Code synchrone, microtasks et macrotasks

JavaScript commence toujours par exécuter le code synchrone. Ensuite, il traite les microtasks, puis les macrotasks.

Type Exemples Priorité
Code synchrone console.log(), calculs, fonctions classiques Exécuté en premier
Microtasks Promise.then(), queueMicrotask(), await Après le synchrone, avant les timers
Macrotasks setTimeout(), setInterval(), événements DOM Après les microtasks

Ordre d'exécution

Dans cet exemple, certaines instructions sont synchrones, d’autres sont placées dans la file des microtasks, et d’autres dans la file des macrotasks.

javascript

// Cette ligne est synchrone.
// Elle est exécutée immédiatement.
console.log('A');

// setTimeout place le callback dans la file des macrotasks.
// Même avec 0 ms, il ne s'exécute pas tout de suite.
setTimeout(() => {
  console.log('B - timer');
}, 0);

// Promise.resolve().then() place le callback dans la file des microtasks.
// Les microtasks passent avant les timers.
Promise.resolve().then(() => {
  console.log('C - microtask');
});

// queueMicrotask place aussi une fonction dans la file des microtasks.
queueMicrotask(() => {
  console.log('D - microtask');
});

// Cette ligne est synchrone.
// Elle s'exécute avant les microtasks et les timers.
console.log('E');

// Ordre attendu :
// A
// E
// C - microtask
// D - microtask
// B - timer
Pourquoi cet ordre ?

JavaScript exécute d’abord tout le code synchrone : A puis E. Ensuite, il vide la file des microtasks : C puis D. Enfin, il exécute la macrotask du setTimeout : B.

Le rôle de la call stack

La call stack, ou pile d’appels, contient les fonctions en cours d’exécution. Tant que la pile n’est pas vide, JavaScript continue d’exécuter le code synchrone.

javascript

// Fonction appelée en troisième.
function fonctionC() {
  console.log('C');
}

// Fonction appelée en deuxième.
function fonctionB() {
  console.log('B');

  // fonctionB appelle fonctionC.
  fonctionC();
}

// Fonction appelée en premier.
function fonctionA() {
  console.log('A');

  // fonctionA appelle fonctionB.
  fonctionB();
}

// On lance la première fonction.
fonctionA();

// Ordre :
// A
// B
// C

/*
  Explication :

  fonctionA entre dans la call stack.
  fonctionA appelle fonctionB.
  fonctionB appelle fonctionC.
  fonctionC se termine.
  fonctionB se termine.
  fonctionA se termine.

  Ensuite seulement, JavaScript peut passer aux tâches asynchrones.
*/

Promises et microtasks

Les callbacks des Promises sont placés dans la file des microtasks. C’est pour cela qu’ils passent avant les timers.

javascript

// Code synchrone.
console.log('1 - début');

// Timer placé dans les macrotasks.
setTimeout(() => {
  console.log('4 - setTimeout');
}, 0);

// Promise placée dans les microtasks.
Promise.resolve().then(() => {
  console.log('3 - Promise.then');
});

// Code synchrone.
console.log('2 - fin');

// Résultat :
// 1 - début
// 2 - fin
// 3 - Promise.then
// 4 - setTimeout
Point important :

Une Promise déjà résolue ne s’exécute pas immédiatement dans le flux synchrone. Son .then() est placé dans les microtasks, donc il attend la fin du code synchrone.

async / await et event loop

await coupe temporairement l’exécution de la fonction async. La suite de la fonction reprend plus tard, comme une microtask.

javascript

// Fonction async.
async function demo() {
  console.log('2 - début async');

  // await attend la résolution de la Promise.
  // La suite de la fonction sera reprise plus tard.
  await Promise.resolve();

  console.log('4 - après await');
}

// Code synchrone.
console.log('1 - avant demo');

// Appel de la fonction async.
demo();

// Code synchrone.
console.log('3 - après demo');

// Résultat :
// 1 - avant demo
// 2 - début async
// 3 - après demo
// 4 - après await
À retenir :

Le début d’une fonction async s’exécute immédiatement. Mais dès que JavaScript rencontre await, la suite est reportée.

Microtasks en chaîne

Les microtasks sont prioritaires. Si tu en crées beaucoup à la suite, elles peuvent retarder les timers et même le rendu visuel de la page.

javascript

// Timer prévu rapidement.
setTimeout(() => {
  console.log('Timer exécuté');
}, 0);

// Fonction qui ajoute plusieurs microtasks.
let compteur = 0;

function ajouterMicrotask() {
  compteur++;

  if (compteur < 5) {
    queueMicrotask(ajouterMicrotask);
  }

  console.log('Microtask', compteur);
}

// On lance la première microtask.
queueMicrotask(ajouterMicrotask);

// Le timer attendra que les microtasks soient terminées.
Attention :

Si tu crées une boucle infinie de microtasks, le navigateur peut ne plus avoir le temps de gérer les timers, les clics ou le rendu de la page.

Macrotasks avec setTimeout

setTimeout() ne garantit pas une exécution exacte au milliseconde près. Il indique seulement un délai minimum avant que le callback puisse être exécuté.

javascript

// Même avec 0 ms, ce callback ne s'exécute pas immédiatement.
setTimeout(() => {
  console.log('Timer terminé');
}, 0);

// Ce code synchrone passe avant le timer.
console.log('Code synchrone terminé');

/*
  Résultat :
  Code synchrone terminé
  Timer terminé
*/

requestAnimationFrame et rendu navigateur

requestAnimationFrame() demande au navigateur d’exécuter une fonction juste avant le prochain rendu visuel. C’est très utile pour les animations.

javascript

// Code synchrone.
console.log('Début');

// Demande au navigateur d'exécuter ce callback
// avant le prochain rendu visuel.
requestAnimationFrame(() => {
  console.log('requestAnimationFrame');
});

// Timer classique.
setTimeout(() => {
  console.log('setTimeout');
}, 0);

// Microtask.
Promise.resolve().then(() => {
  console.log('Promise');
});

console.log('Fin');

/*
  L'ordre exact entre requestAnimationFrame et setTimeout peut dépendre
  du contexte navigateur et du cycle de rendu.

  Mais le principe important reste :
  - le code synchrone passe d'abord
  - les microtasks passent ensuite
  - le rendu et les timers sont orchestrés par le navigateur
*/
Bon réflexe :

Pour les animations visuelles calculées en JavaScript, préfère requestAnimationFrame() à setInterval(). Le navigateur pourra mieux synchroniser l’animation avec l’affichage.

Pourquoi c'est important

  • Les microtasks passent avant les timers.
  • Les Promises utilisent la file des microtasks.
  • Le code synchrone bloque tout tant qu’il n’est pas terminé.
  • Un excès de microtasks peut retarder le rendu de la page.
  • setTimeout(..., 0) ne signifie pas “exécuter immédiatement”.
  • await reporte la suite de la fonction async dans une microtask.

Résumé rapide

Élément File / mécanisme Exemple
Code synchrone Call stack console.log(), fonctions classiques
Microtask Microtask queue Promise.then(), queueMicrotask()
Macrotask Task queue setTimeout(), setInterval()
Animation Cycle de rendu requestAnimationFrame()
Résumé simple :

JavaScript exécute d’abord le code synchrone, puis vide les microtasks, puis passe aux macrotasks comme les timers. L’event loop permet de coordonner tout cela avec les événements utilisateur et le rendu du navigateur.

// 15 — ERREURS

Gestion des erreurs JavaScript

Une bonne gestion des erreurs évite les pages qui cassent silencieusement. Elle permet d’afficher un message clair à l’utilisateur, de comprendre ce qui s’est passé, et d’éviter qu’une seule erreur bloque toute l’application.

À quoi ça sert ?

La gestion d’erreurs est indispensable dans les vrais projets : formulaire invalide, JSON mal formé, API indisponible, données manquantes, problème réseau, utilisateur non connecté, fichier introuvable, etc.

try / catch / finally

Le bloc try / catch permet d’essayer d’exécuter du code qui peut échouer. Si une erreur arrive dans le try, JavaScript saute directement dans le catch. Le bloc finally, lui, s’exécute dans tous les cas.

javascript

// Fonction qui essaie de transformer une chaîne JSON en objet JavaScript.
function parserJSON(raw) {
  try {
    /*
      Le code placé dans try est le code qui peut échouer.

      JSON.parse() peut provoquer une erreur si le texte reçu
      n'est pas un JSON valide.
    */
    const data = JSON.parse(raw);

    /*
      Si JSON.parse() réussit, on retourne un objet avec ok: true.

      Cette structure est pratique car elle évite de faire planter
      le reste du programme.
    */
    return {
      ok: true,
      data: data
    };
  } catch (err) {
    /*
      Le catch récupère l'erreur si le try échoue.

      err contient l'objet d'erreur.
      err.message contient généralement le message lisible.
    */
    return {
      ok: false,
      error: err.message
    };
  } finally {
    /*
      finally s'exécute toujours :
      - si le try réussit
      - si le catch récupère une erreur
      - même si on fait un return avant

      C'est utile pour arrêter un loader,
      fermer une connexion,
      réactiver un bouton, etc.
    */
    console.log('Parsing terminé');
  }
}

// Exemple avec un JSON valide.
const resultat = parserJSON('{ "nom": "Julien" }');

// On vérifie si le parsing a réussi.
if (resultat.ok) {
  console.log(resultat.data.nom);
} else {
  console.error(resultat.error);
}
À retenir :

Utilise try pour le code risqué, catch pour gérer l’erreur, et finally pour exécuter une action quoi qu’il arrive.

Exemple avec JSON invalide

Cet exemple montre ce qui se passe quand JSON.parse() reçoit une chaîne incorrecte.

javascript

// JSON invalide : il manque des guillemets autour de nom.
const mauvaisJSON = '{ nom: "Julien" }';

const test = parserJSON(mauvaisJSON);

if (!test.ok) {
  /*
    Ici, au lieu de casser toute la page,
    on récupère proprement le message d'erreur.
  */
  console.error('JSON invalide :', test.error);
}

Lancer une erreur avec throw

Le mot-clé throw permet de créer volontairement une erreur. C’est utile quand une fonction reçoit une valeur invalide.

javascript

// Fonction qui calcule un prix TTC.
function calculerTTC(prixHT, tauxTVA) {
  /*
    On vérifie que prixHT est bien un nombre.
    Si ce n'est pas le cas, on lance une erreur.
  */
  if (typeof prixHT !== 'number') {
    throw new Error('Le prix HT doit être un nombre');
  }

  /*
    On vérifie que le taux de TVA est aussi un nombre.
  */
  if (typeof tauxTVA !== 'number') {
    throw new Error('Le taux de TVA doit être un nombre');
  }

  return prixHT * (1 + tauxTVA);
}

try {
  const total = calculerTTC(100, 0.2);

  console.log(total);
} catch (err) {
  /*
    Si calculerTTC() lance une erreur,
    elle est récupérée ici.
  */
  console.error(err.message);
}
Important :

throw interrompt immédiatement l’exécution de la fonction. Le code situé après le throw ne sera pas exécuté.

Erreurs personnalisées

On peut créer nos propres classes d’erreurs en héritant de Error. C’est très pratique pour distinguer une erreur API, une erreur de validation, une erreur d’authentification, etc.

javascript

// Classe d'erreur personnalisée pour les erreurs API.
class ApiError extends Error {
  constructor(message, status, data = null) {
    /*
      super(message) appelle le constructeur de la classe Error.

      Cela permet à notre ApiError d'avoir un vrai message d'erreur.
    */
    super(message);

    /*
      name permet d'identifier le type de l'erreur.
      Cela aide au debug.
    */
    this.name = 'ApiError';

    /*
      status contient le code HTTP.
      Exemple : 404, 401, 500.
    */
    this.status = status;

    /*
      data peut contenir des informations supplémentaires :
      réponse API, erreurs de formulaire, détails serveur, etc.
    */
    this.data = data;
  }
}

// Exemple : on lance une erreur API personnalisée.
throw new ApiError('Utilisateur introuvable', 404);

Utiliser une erreur personnalisée

Une fois la classe créée, on peut détecter précisément ce type d’erreur avec instanceof.

javascript

// Fonction qui simule la récupération d'un utilisateur.
function getUtilisateur(id) {
  if (!id) {
    throw new ApiError('ID utilisateur manquant', 400);
  }

  if (id === 999) {
    throw new ApiError('Utilisateur introuvable', 404);
  }

  return {
    id: id,
    prenom: 'Julien'
  };
}

try {
  const user = getUtilisateur(999);

  console.log(user);
} catch (err) {
  /*
    instanceof permet de vérifier si l'erreur vient de notre classe ApiError.
  */
  if (err instanceof ApiError) {
    console.error('Erreur API :', err.message);
    console.error('Statut HTTP :', err.status);
  } else {
    /*
      Ici, on gère les autres erreurs non prévues.
    */
    console.error('Erreur inconnue :', err);
  }
}

Gestion des erreurs avec async / await

Avec async / await, on utilise souvent try / catch pour gérer les erreurs asynchrones.

javascript

// Fonction async qui récupère des données depuis une API.
async function chargerUtilisateur(id) {
  try {
    const reponse = await fetch(`/api/users/${id}`);

    /*
      fetch ne déclenche pas automatiquement une erreur
      pour les statuts HTTP comme 404 ou 500.

      Il faut donc vérifier reponse.ok.
    */
    if (!reponse.ok) {
      throw new ApiError(
        `Erreur HTTP ${reponse.status}`,
        reponse.status
      );
    }

    const data = await reponse.json();

    return data;
  } catch (err) {
    /*
      Le catch récupère :
      - les erreurs réseau
      - les erreurs lancées avec throw
      - les erreurs de JSON
    */
    console.error('Impossible de charger utilisateur :', err);

    /*
      On relance l'erreur pour que le code appelant
      puisse aussi la gérer.
    */
    throw err;
  }
}

// Exemple d'utilisation.
async function afficherUtilisateur() {
  try {
    const user = await chargerUtilisateur(1);

    console.log(user);
  } catch (err) {
    if (err instanceof ApiError && err.status === 404) {
      console.log('Utilisateur introuvable');
      return;
    }

    console.log('Une erreur est survenue');
  }
}

afficherUtilisateur();
Bon réflexe :

Avec fetch(), vérifie toujours response.ok. Sinon, une réponse 404 ou 500 peut passer comme une réponse normale.

Erreur de validation

Les erreurs ne viennent pas seulement du serveur. Une erreur peut aussi venir d’un formulaire mal rempli.

javascript

// Classe personnalisée pour les erreurs de formulaire.
class ValidationError extends Error {
  constructor(message, champ) {
    super(message);

    this.name = 'ValidationError';

    /*
      champ indique le champ concerné par l'erreur.
      Exemple : email, motDePasse, nom, montant, etc.
    */
    this.champ = champ;
  }
}

// Fonction de validation simple.
function validerEmail(email) {
  if (!email) {
    throw new ValidationError('Email obligatoire', 'email');
  }

  if (!email.includes('@')) {
    throw new ValidationError('Email invalide', 'email');
  }

  return true;
}

try {
  validerEmail('julien-email.com');
} catch (err) {
  if (err instanceof ValidationError) {
    console.error(`Erreur sur le champ ${err.champ} : ${err.message}`);
  }
}

Ne pas avaler les erreurs silencieusement

Une erreur fréquente consiste à mettre un catch vide. Le problème disparaît visuellement, mais le bug existe toujours.

javascript

// Mauvaise pratique.
try {
  JSON.parse('{ mauvais json }');
} catch (err) {
  /*
    Catch vide : mauvaise idée.

    L'erreur est cachée.
    Tu ne sais plus ce qui s'est passé.
  */
}

// Meilleure pratique.
try {
  JSON.parse('{ mauvais json }');
} catch (err) {
  /*
    On garde au minimum une trace de l'erreur.
  */
  console.error('Erreur JSON :', err.message);
}
Anti-pattern :

Éviter les catch vides. Ils cachent les vrais problèmes et rendent le debug beaucoup plus difficile.

Gestion globale des erreurs

On peut écouter certaines erreurs globales avec window.addEventListener(). Cela ne remplace pas les try / catch, mais peut aider à détecter des erreurs non prévues.

javascript

// Écoute les erreurs JavaScript non capturées.
window.addEventListener('error', (event) => {
  console.error('Erreur globale :', event.message);
  console.error('Fichier :', event.filename);
  console.error('Ligne :', event.lineno);
});

// Écoute les Promises rejetées sans catch.
window.addEventListener('unhandledrejection', (event) => {
  console.error('Promise rejetée non gérée :', event.reason);
});
Attention :

La gestion globale doit servir de filet de sécurité. Le mieux reste de gérer les erreurs localement là où elles peuvent arriver : formulaire, appel API, parsing JSON, action utilisateur, etc.

Afficher un message propre à l’utilisateur

En production, il ne faut pas toujours afficher l’erreur technique brute à l’utilisateur. Il vaut mieux afficher un message clair, puis garder le détail technique pour le debug.

javascript

// Fonction qui transforme une erreur technique en message utilisateur.
function messageUtilisateur(err) {
  if (err instanceof ApiError) {
    if (err.status === 401) {
      return 'Vous devez vous reconnecter.';
    }

    if (err.status === 404) {
      return 'La ressource demandée est introuvable.';
    }

    if (err.status >= 500) {
      return 'Le serveur rencontre un problème. Réessayez plus tard.';
    }
  }

  if (err instanceof ValidationError) {
    return err.message;
  }

  return 'Une erreur inattendue est survenue.';
}

try {
  throw new ApiError('Erreur serveur', 500);
} catch (err) {
  const message = messageUtilisateur(err);

  console.log(message);
}

Notion Rôle
try Contient le code qui peut échouer.
catch Récupère et traite l’erreur.
finally S’exécute dans tous les cas.
throw Lance volontairement une erreur.
Error Classe native pour représenter une erreur.
extends Error Permet de créer une erreur personnalisée.
instanceof Vérifie le type d’une erreur.
unhandledrejection Détecte les Promises rejetées sans catch.
Résumé simple :

Une bonne gestion d’erreurs ne consiste pas seulement à éviter les bugs. Elle sert aussi à comprendre les problèmes, protéger l’expérience utilisateur, afficher des messages propres et rendre ton application plus fiable.

// 16 — DOM

DOM moderne et événements

Le DOM, pour Document Object Model, est la représentation objet de ta page HTML. Grâce au DOM, JavaScript peut lire les éléments HTML, modifier leur contenu, changer leurs classes CSS, créer de nouveaux éléments et écouter les interactions utilisateur.

À quoi ça sert ?

Le DOM est indispensable pour créer des pages interactives : menu burger, modal, todo list, formulaire dynamique, compteur, accordéon, suppression d’éléments, affichage de messages d’erreur, ajout de cartes, etc.

Sélectionner des éléments

Avant de modifier un élément HTML, il faut d’abord le sélectionner avec JavaScript. Les méthodes les plus utilisées aujourd’hui sont querySelector() et querySelectorAll().

javascript

// Sélectionne le premier élément h1 trouvé dans la page.
const titre = document.querySelector('h1');

// Sélectionne un élément par son id.
// Ici, on cherche id="menu".
const menu = document.querySelector('#menu');

// Sélectionne un élément par sa classe.
// Ici, on cherche class="card".
const carte = document.querySelector('.card');

// Sélectionne tous les boutons de la page.
// querySelectorAll retourne une NodeList.
const boutons = document.querySelectorAll('button');

// On peut parcourir une NodeList avec forEach().
boutons.forEach((bouton) => {
  console.log(bouton.textContent);
});
À retenir :

querySelector() retourne le premier élément trouvé. querySelectorAll() retourne tous les éléments correspondants. Les sélecteurs utilisés sont les mêmes qu’en CSS : #id, .classe, balise, etc.

Sélection et modification

Une fois un élément sélectionné, on peut modifier son texte, ses classes CSS, ses attributs ou son style.

javascript

// On sélectionne le premier h1 de la page.
const titre = document.querySelector('h1');

// Bonne pratique : on vérifie que l'élément existe.
// Cela évite une erreur si aucun h1 n'est trouvé.
if (titre) {
  // textContent modifie le texte de l'élément.
  titre.textContent = 'Nouveau titre';

  // classList.add() ajoute une classe CSS.
  titre.classList.add('active');

  // classList.remove() retire une classe CSS.
  titre.classList.remove('ancien-style');

  // classList.toggle() ajoute ou retire une classe comme un interrupteur.
  titre.classList.toggle('highlight');

  // setAttribute() ajoute ou modifie un attribut HTML.
  titre.setAttribute('title', 'Titre modifié avec JavaScript');
}

// On crée un nouvel élément button.
const bouton = document.createElement('button');

// On ajoute du texte dans le bouton.
bouton.textContent = 'Cliquer';

// On ajoute une classe CSS au bouton.
bouton.classList.add('btn');

// On ajoute le bouton à la fin du body.
document.body.appendChild(bouton);
Important :

Si querySelector() ne trouve rien, il retourne null. Avant d’utiliser textContent, classList ou addEventListener, vérifie que l’élément existe.

textContent, innerHTML et value

Ces trois propriétés sont souvent confondues. Elles ne servent pas exactement à la même chose.

javascript

// textContent modifie uniquement le texte.
// Le HTML est affiché comme du texte simple.
const message = document.querySelector('#message');

if (message) {
  message.textContent = 'Message ajouté avec JavaScript';
}

// innerHTML permet d'insérer du HTML.
// Attention : à utiliser prudemment avec des données utilisateur.
const bloc = document.querySelector('#bloc');

if (bloc) {
  bloc.innerHTML = '<strong>Texte important</strong>';
}

// value sert à récupérer ou modifier la valeur d'un input.
const input = document.querySelector('#prenom');

if (input) {
  input.value = 'Julien';

  console.log(input.value);
}
Sécurité :

Évite d’utiliser innerHTML avec du texte saisi par un utilisateur, car cela peut créer une faille XSS si le contenu n’est pas sécurisé. Pour du texte simple, préfère textContent.

Créer des éléments dynamiquement

JavaScript peut créer des éléments HTML, leur ajouter du contenu, des classes, des attributs, puis les insérer dans la page.

javascript

// On sélectionne la liste.
const liste = document.querySelector('#liste');

// Fonction qui ajoute une tâche dans la liste.
function ajouterTache(texte) {
  // On vérifie que la liste existe.
  if (!liste) {
    return;
  }

  // Création d'un élément li.
  const li = document.createElement('li');

  // Création d'un span pour le texte de la tâche.
  const span = document.createElement('span');
  span.textContent = texte;

  // Création du bouton de suppression.
  const boutonSupprimer = document.createElement('button');
  boutonSupprimer.textContent = 'X';

  // On ajoute un attribut data-delete.
  // Il servira plus tard pour l'event delegation.
  boutonSupprimer.dataset.delete = 'true';

  // On ajoute le span et le bouton dans le li.
  li.appendChild(span);
  li.appendChild(boutonSupprimer);

  // On ajoute le li dans la liste.
  liste.appendChild(li);
}

// Exemple d'utilisation.
ajouterTache('Apprendre le DOM');
ajouterTache('Créer une todo list');
Pourquoi créer les éléments avec createElement ?

C’est plus propre et plus sûr que de construire de longues chaînes HTML. Tu peux contrôler chaque élément, ajouter des classes, des attributs et des événements plus facilement.

Écouter un événement

Un événement représente une action : clic, saisie clavier, soumission de formulaire, mouvement de souris, chargement de page, etc.

javascript

// On récupère un bouton.
const boutonAction = document.querySelector('#boutonAction');

// On vérifie qu'il existe.
if (boutonAction) {
  // addEventListener écoute un événement.
  // Ici, on écoute le clic.
  boutonAction.addEventListener('click', () => {
    console.log('Bouton cliqué');
  });
}

Récupérer la valeur d’un input

Pour récupérer ce qu’un utilisateur saisit dans un champ, on utilise généralement la propriété value.

javascript

// On récupère l'input, le bouton et la zone d'affichage.
const inputPrenom = document.querySelector('#prenom');
const boutonValider = document.querySelector('#valider');
const resultat = document.querySelector('#resultat');

if (inputPrenom && boutonValider && resultat) {
  boutonValider.addEventListener('click', () => {
    // value récupère le texte saisi dans l'input.
    const prenom = inputPrenom.value.trim();

    // trim() retire les espaces au début et à la fin.
    if (prenom === '') {
      resultat.textContent = 'Veuillez entrer un prénom.';
      return;
    }

    resultat.textContent = `Bonjour ${prenom}`;
  });
}

Formulaire et preventDefault

Par défaut, un formulaire HTML recharge souvent la page à la soumission. Avec JavaScript, on utilise event.preventDefault() pour empêcher ce comportement et gérer le formulaire nous-mêmes.

javascript

// On sélectionne le formulaire.
const formulaire = document.querySelector('#formulaireContact');

if (formulaire) {
  formulaire.addEventListener('submit', (event) => {
    /*
      Empêche le rechargement automatique de la page.
      Cela permet de traiter le formulaire en JavaScript.
    */
    event.preventDefault();

    // FormData récupère les champs du formulaire.
    const formData = new FormData(formulaire);

    // On récupère une valeur par son attribut name.
    const email = formData.get('email');

    console.log('Email envoyé :', email);
  });
}

Event delegation

L’event delegation consiste à écouter un événement sur un parent, puis à détecter quel enfant a été cliqué.

Pourquoi c’est utile ?

Si tu ajoutes des éléments dynamiquement, ils n’existent pas au chargement de la page. Au lieu d’ajouter un événement à chaque bouton, tu écoutes le clic sur le parent. C’est parfait pour les todo lists, tableaux, cartes, listes de dépenses, etc.

javascript

// On sélectionne la liste parent.
const liste = document.querySelector('#liste');

if (liste) {
  // On écoute les clics sur la liste entière.
  liste.addEventListener('click', (event) => {
    /*
      event.target représente l'élément exact qui a été cliqué.

      closest('[data-delete]') cherche l'élément cliqué
      ou un de ses parents qui possède l'attribut data-delete.
    */
    const bouton = event.target.closest('[data-delete]');

    // Si aucun bouton de suppression n'a été cliqué, on arrête la fonction.
    if (!bouton) {
      return;
    }

    // On cherche le li le plus proche du bouton.
    const li = bouton.closest('li');

    // Si le li existe, on le supprime.
    if (li) {
      li.remove();
    }
  });
}
À retenir :

event.target indique l’élément cliqué. closest() remonte dans le DOM jusqu’à trouver un élément correspondant au sélecteur donné.

Bubbling et propagation

Quand tu cliques sur un élément, l’événement remonte dans ses parents. Ce mécanisme s’appelle le bubbling.

javascript

// Exemple : une carte contient un bouton.
const carteProjet = document.querySelector('.project-card');
const boutonProjet = document.querySelector('.project-card button');

if (carteProjet && boutonProjet) {
  carteProjet.addEventListener('click', () => {
    console.log('Carte cliquée');
  });

  boutonProjet.addEventListener('click', (event) => {
    /*
      stopPropagation empêche l'événement de remonter au parent.

      Sans cette ligne, cliquer sur le bouton déclencherait aussi
      le click de la carte.
    */
    event.stopPropagation();

    console.log('Bouton cliqué');
  });
}

dataset

Les attributs data-* permettent de stocker de petites informations directement dans le HTML. JavaScript peut les lire avec dataset.

javascript

// Exemple HTML imaginé :
// <button data-id="12" data-action="delete">Supprimer</button>

const boutonData = document.querySelector('[data-action]');

if (boutonData) {
  // dataset.id récupère data-id.
  const id = boutonData.dataset.id;

  // dataset.action récupère data-action.
  const action = boutonData.dataset.action;

  console.log(id);
  console.log(action);
}

DOMContentLoaded

Si ton script est chargé avant le HTML, certains éléments peuvent ne pas encore exister. L’événement DOMContentLoaded permet d’attendre que la structure HTML soit prête.

javascript

document.addEventListener('DOMContentLoaded', () => {
  /*
    Ce code s'exécute quand le HTML est chargé.

    C'est un bon endroit pour sélectionner les éléments
    et brancher les événements.
  */
  const bouton = document.querySelector('#start');

  if (bouton) {
    bouton.addEventListener('click', () => {
      console.log('Page prête, bouton actif');
    });
  }
});

Exemple complet : mini liste dynamique

Cet exemple regroupe plusieurs notions : sélection DOM, création d’éléments, lecture d’input, ajout dans une liste et suppression par event delegation.

javascript

// Sélection des éléments.
const inputTache = document.querySelector('#tacheInput');
const boutonAjouter = document.querySelector('#ajouterBtn');
const listeTaches = document.querySelector('#listeTaches');
const messageErreur = document.querySelector('#erreur');

function afficherErreur(message) {
  if (messageErreur) {
    messageErreur.textContent = message;
  }
}

function ajouterTacheDOM(texte) {
  if (!listeTaches) {
    return;
  }

  // Création du li.
  const li = document.createElement('li');

  // Création du texte.
  const span = document.createElement('span');
  span.textContent = texte;

  // Création du bouton supprimer.
  const btn = document.createElement('button');
  btn.textContent = 'X';
  btn.dataset.delete = 'true';

  // Assemblage.
  li.appendChild(span);
  li.appendChild(btn);

  // Ajout dans la liste.
  listeTaches.appendChild(li);
}

if (inputTache && boutonAjouter) {
  boutonAjouter.addEventListener('click', () => {
    const texte = inputTache.value.trim();

    if (texte === '') {
      afficherErreur('Veuillez entrer une tâche.');
      return;
    }

    afficherErreur('');
    ajouterTacheDOM(texte);

    // On vide l'input après ajout.
    inputTache.value = '';
  });
}

if (listeTaches) {
  listeTaches.addEventListener('click', (event) => {
    const bouton = event.target.closest('[data-delete]');

    if (!bouton) {
      return;
    }

    const li = bouton.closest('li');

    if (li) {
      li.remove();
    }
  });
}

// 17 — TABLEAUX

Méthodes de tableaux avancées

Les méthodes de tableaux sont indispensables pour manipuler des listes de données. En JavaScript, tu les utiliseras partout : produits, dépenses, recettes, tâches, utilisateurs, articles, cryptos, transactions, paniers, formulaires, etc.

À quoi ça sert ?

Les méthodes comme map(), filter(), reduce() et sort() permettent de transformer, filtrer, calculer et trier des données proprement, sans écrire trop de boucles manuelles.

Données de départ

Pour les exemples, on part d’un tableau d’objets représentant des produits.

javascript

// Tableau d'objets.
// Chaque produit possède un nom, un prix et un stock.
const produits = [
  { nom: 'Clavier', prix: 49, stock: 12 },
  { nom: 'Écran', prix: 199, stock: 4 },
  { nom: 'Souris', prix: 29, stock: 30 }
];

map()

map() sert à transformer chaque élément d’un tableau. Elle retourne toujours un nouveau tableau de même longueur.

Idée simple :

Utilise map() quand tu veux convertir une liste en une autre liste : récupérer seulement les noms, formater des prix, créer du HTML, transformer des objets, etc.

javascript

// map() parcourt chaque produit.
// Pour chaque produit, on retourne seulement son nom.
const noms = produits.map((produit) => {
  return produit.nom;
});

console.log(noms);
// Résultat : ['Clavier', 'Écran', 'Souris']

// Version courte avec une arrow function implicite.
const prix = produits.map((produit) => produit.prix);

console.log(prix);
// Résultat : [49, 199, 29]

// Exemple : créer un nouveau tableau avec un prix formaté.
const produitsFormates = produits.map((produit) => {
  return {
    nom: produit.nom,
    prix: `${produit.prix} €`,
    stock: produit.stock
  };
});

console.log(produitsFormates);
À retenir :

map() ne sert pas à filtrer. Elle sert à transformer. Si ton tableau contient 3 éléments au départ, le tableau retourné contiendra aussi 3 éléments.

filter()

filter() sert à garder seulement certains éléments d’un tableau. Elle retourne un nouveau tableau contenant les éléments qui passent une condition.

javascript

// filter() parcourt chaque produit.
// Si la condition retourne true, le produit est gardé.
// Si la condition retourne false, le produit est ignoré.
const disponibles = produits.filter((produit) => {
  return produit.stock > 0;
});

console.log(disponibles);

// Version courte.
const produitsChers = produits.filter((produit) => produit.prix > 50);

console.log(produitsChers);
// Résultat : [{ nom: 'Écran', prix: 199, stock: 4 }]

// Exemple avec plusieurs conditions.
// On garde les produits qui coûtent moins de 100 €
// et qui ont au moins 10 unités en stock.
const bonsPlans = produits.filter((produit) => {
  return produit.prix < 100 && produit.stock >= 10;
});

console.log(bonsPlans);
À retenir :

filter() sert à réduire une liste. Le tableau retourné peut contenir moins d’éléments que le tableau de départ.

reduce()

reduce() sert à réduire un tableau en une seule valeur : une somme, un total, une moyenne, un objet groupé, un compteur, etc.

Idée simple :

reduce() utilise un accumulateur. Cet accumulateur garde le résultat au fur et à mesure du parcours du tableau.

javascript

// Objectif : calculer le stock total de tous les produits.
const totalStock = produits.reduce((somme, produit) => {
  /*
    somme est l'accumulateur.

    Au départ, somme vaut 0,
    car on a mis 0 comme valeur initiale après la virgule.
  */
  return somme + produit.stock;
}, 0);

console.log(totalStock);
// Résultat : 46

// Objectif : calculer la valeur totale du stock.
// Pour chaque produit : prix * stock.
const valeurStock = produits.reduce((total, produit) => {
  return total + produit.prix * produit.stock;
}, 0);

console.log(valeurStock);
Important :

Pense souvent à mettre une valeur initiale à reduce(). Pour une somme, on met généralement 0. Pour un tableau, on met []. Pour un objet, on met {}.

sort()

sort() sert à trier un tableau. Attention : contrairement à map() et filter(), sort() modifie le tableau original.

Bon réflexe :

Pour éviter de modifier le tableau original, fais une copie avant de trier : [...produits].sort(...).

javascript

// Tri par prix croissant.
// On copie d'abord le tableau avec [...produits]
// pour ne pas modifier le tableau original.
const parPrixCroissant = [...produits].sort((a, b) => {
  return a.prix - b.prix;
});

console.log(parPrixCroissant);

// Tri par prix décroissant.
const parPrixDecroissant = [...produits].sort((a, b) => {
  return b.prix - a.prix;
});

console.log(parPrixDecroissant);

// Tri par stock croissant.
const parStockCroissant = [...produits].sort((a, b) => {
  return a.stock - b.stock;
});

console.log(parStockCroissant);

// Tri alphabétique par nom.
// localeCompare() compare proprement deux chaînes de caractères.
const parNom = [...produits].sort((a, b) => {
  return a.nom.localeCompare(b.nom);
});

console.log(parNom);
Comprendre le callback de sort :

Si le résultat est négatif, a passe avant b. Si le résultat est positif, b passe avant a. Si le résultat vaut 0, l’ordre reste équivalent.

map, filter, reduce, sort ensemble

Voici un exemple complet avec les quatre méthodes principales.

javascript

// Récupérer uniquement les noms.
const noms = produits.map((p) => p.nom);

// Garder les produits disponibles.
const disponibles = produits.filter((p) => p.stock > 0);

// Calculer le stock total.
const totalStock = produits.reduce((somme, p) => {
  return somme + p.stock;
}, 0);

// Trier par prix croissant sans modifier le tableau original.
const parPrix = [...produits].sort((a, b) => a.prix - b.prix);

console.log(noms);
console.log(disponibles);
console.log(totalStock);
console.log(parPrix);

Chaîner plusieurs méthodes

On peut chaîner plusieurs méthodes de tableaux pour créer des traitements puissants et lisibles.

javascript

// Objectif :
// 1. Garder les produits en stock
// 2. Trier par prix croissant
// 3. Récupérer uniquement les noms
const nomsProduitsDisponibles = produits
  .filter((produit) => produit.stock > 0)
  .sort((a, b) => a.prix - b.prix)
  .map((produit) => produit.nom);

console.log(nomsProduitsDisponibles);
Attention avec sort dans une chaîne :

sort() modifie le tableau sur lequel il est appelé. Si tu veux être vraiment prudent, copie le tableau avant : [...produits].filter(...).sort(...).map(...).

find() et findIndex()

find() sert à trouver le premier élément qui respecte une condition. findIndex() retourne sa position dans le tableau.

javascript

// find() retourne le premier produit dont le nom est 'Écran'.
const ecran = produits.find((produit) => {
  return produit.nom === 'Écran';
});

console.log(ecran);

// Si aucun élément n'est trouvé, find() retourne undefined.
const casque = produits.find((produit) => produit.nom === 'Casque');

console.log(casque);

// findIndex() retourne l'index du premier élément trouvé.
const indexSouris = produits.findIndex((produit) => {
  return produit.nom === 'Souris';
});

console.log(indexSouris);

// Si aucun élément n'est trouvé, findIndex() retourne -1.

some() et every()

some() vérifie si au moins un élément respecte une condition. every() vérifie si tous les éléments respectent une condition.

javascript

// some() retourne true si au moins un produit coûte plus de 100 €.
const existeProduitCher = produits.some((produit) => {
  return produit.prix > 100;
});

console.log(existeProduitCher);
// Résultat : true

// every() retourne true si tous les produits sont en stock.
const tousEnStock = produits.every((produit) => {
  return produit.stock > 0;
});

console.log(tousEnStock);
// Résultat : true

// Exemple : vérifier si tous les prix sont positifs.
const prixValides = produits.every((produit) => produit.prix >= 0);

console.log(prixValides);

includes()

includes() vérifie si un tableau contient une valeur précise. C’est surtout pratique avec les tableaux de valeurs simples.

javascript

const langages = ['HTML', 'CSS', 'JavaScript', 'TypeScript'];

console.log(langages.includes('JavaScript'));
// Résultat : true

console.log(langages.includes('PHP'));
// Résultat : false

// Exemple avec une condition.
if (langages.includes('TypeScript')) {
  console.log('TypeScript est dans la liste');
}

forEach()

forEach() sert à exécuter une action pour chaque élément. Contrairement à map(), elle ne retourne pas un nouveau tableau.

javascript

// forEach() est utile pour afficher,
// créer des éléments DOM,
// ou exécuter une action pour chaque élément.
produits.forEach((produit) => {
  console.log(`${produit.nom} coûte ${produit.prix} €`);
});

// Exemple DOM imaginaire.
const listeProduits = document.querySelector('#listeProduits');

if (listeProduits) {
  produits.forEach((produit) => {
    const li = document.createElement('li');

    li.textContent = `${produit.nom} — ${produit.prix} €`;

    listeProduits.appendChild(li);
  });
}
map ou forEach ?

Utilise map() quand tu veux créer un nouveau tableau. Utilise forEach() quand tu veux simplement exécuter une action.

groupBy manuel avec reduce()

On peut utiliser reduce() pour regrouper des données dans un objet. C’est très utile pour classer des dépenses par type, des recettes par catégorie, des articles par statut, etc.

javascript

const transactions = [
  { type: 'revenu', montant: 1200 },
  { type: 'depense', montant: 80 },
  { type: 'depense', montant: 25 }
];

// Objectif : regrouper les transactions par type.
const groupes = transactions.reduce((acc, transaction) => {
  /*
    acc est l'accumulateur.

    Ici, acc est un objet qui va progressivement devenir :
    {
      revenu: [...],
      depense: [...]
    }
  */

  // On récupère la clé de regroupement.
  const cle = transaction.type;

  /*
    Si acc[cle] n'existe pas encore,
    on crée un tableau vide pour ce type.
  */
  if (!acc[cle]) {
    acc[cle] = [];
  }

  /*
    On ajoute la transaction dans le bon groupe.
  */
  acc[cle].push(transaction);

  /*
    On retourne toujours l'accumulateur
    pour le prochain tour de reduce().
  */
  return acc;
}, {});

console.log(groupes);

Calculer des totaux par catégorie

Avec reduce(), on peut aussi calculer directement un total par catégorie.

javascript

const depenses = [
  { categorie: 'courses', montant: 45 },
  { categorie: 'loyer', montant: 700 },
  { categorie: 'courses', montant: 30 },
  { categorie: 'transport', montant: 60 }
];

// Objectif : obtenir un total par catégorie.
const totauxParCategorie = depenses.reduce((acc, depense) => {
  const categorie = depense.categorie;

  /*
    Si la catégorie n'existe pas encore dans l'accumulateur,
    on l'initialise à 0.
  */
  if (!acc[categorie]) {
    acc[categorie] = 0;
  }

  /*
    On ajoute le montant de la dépense
    au total de la catégorie.
  */
  acc[categorie] += depense.montant;

  return acc;

Architecture simple d'un projet JS

Quand un fichier JavaScript devient trop long, il devient plus difficile à lire, à corriger et à faire évoluer. L’objectif d’une bonne architecture est de séparer les responsabilités : API, stockage, composants visuels, fonctions utilitaires, logique principale, etc.

À quoi ça sert ?

Une architecture propre permet de retrouver plus facilement ton code, de corriger les bugs plus vite, de réutiliser certaines fonctions, et d’éviter d’avoir un seul énorme fichier script.js impossible à maintenir.

Principe de base : une responsabilité par fichier

Chaque fichier doit avoir un rôle clair. Par exemple, un fichier pour le stockage, un fichier pour les appels API, un fichier pour les dates, un fichier pour une modale, etc.

/api Gérer les appels vers le serveur ou une API externe. users.api.js, client.js
/components Gérer les blocs d’interface réutilisables. modal.js, tabs.js
/storage Gérer le localStorage ou sessionStorage. storage.js
/utils Stocker les petites fonctions réutilisables. dates.js, formatters.js
main.js Point d’entrée principal du projet. Initialisation de l’application.

Voici un exemple simple de structure pour un projet JavaScript moderne.

  /storage
    storage.js

    dates.js

  main.js
  styles.css
Résumé simple :

Module storage

Le module storage.js centralise la lecture et l’écriture dans localStorage. Comme ça, tu n’écris pas JSON.stringify() et JSON.parse() partout dans ton projet.

javascript

// FICHIER : /src/storage/storage.js

/*
  Cette fonction lit une donnée dans localStorage.

  cle : nom de la donnée à récupérer.
  defaut : valeur retournée si la donnée n'existe pas ou si une erreur arrive.
*/
export function lire(cle, defaut = null) {
  try {
    // On récupère la donnée brute depuis localStorage.
    const raw = localStorage.getItem(cle);

    // Si aucune donnée n'existe pour cette clé,
    // on retourne la valeur par défaut.
    if (raw === null) {
      return defaut;
    }

    // Si une donnée existe, on la transforme en vraie valeur JavaScript.
    return JSON.parse(raw);
  } catch (err) {
    // Si le JSON est invalide ou si localStorage pose problème,
    // on retourne la valeur par défaut.
    console.warn('Erreur lecture localStorage :', err);

    return defaut;
  }
}

/*
  Cette fonction sauvegarde une donnée dans localStorage.

  Elle transforme automatiquement les objets et tableaux en JSON.
*/
export function sauver(cle, valeur) {
  try {
    localStorage.setItem(cle, JSON.stringify(valeur));

    return true;
  } catch (err) {
    console.warn('Erreur sauvegarde localStorage :', err);

    return false;
  }
}

/*
  Cette fonction supprime une donnée précise du localStorage.
*/
export function supprimer(cle) {
  try {
    localStorage.removeItem(cle);
  } catch (err) {
    console.warn('Erreur suppression localStorage :', err);
  }
}

Module API client

Le fichier client.js peut contenir une fonction générique pour faire des appels API. Cela évite de répéter fetch(), les headers, la vérification response.ok et la conversion JSON partout.

javascript

// FICHIER : /src/api/client.js

// URL de base de l'API.
const API_BASE = 'https://api.example.com';

/*
  Fonction générique pour appeler une API.

  endpoint : chemin de l'API, exemple "/users".
  options : méthode, headers, body, etc.
*/
export async function apiClient(endpoint, options = {}) {
  // On prépare l'URL complète.
  const url = `${API_BASE}${endpoint}`;

  // On lance la requête.
  const response = await fetch(url, {
    // On reprend les options envoyées.
    ...options,

    // On fusionne les headers par défaut et les headers personnalisés.
    headers: {
      'Content-Type': 'application/json',
      ...options.headers
    }
  });

  // Si le serveur répond avec une erreur HTTP,
  // on lance une vraie erreur JavaScript.
  if (!response.ok) {
    throw new Error(`Erreur HTTP ${response.status}`);
  }

  // Si la réponse est vide, on retourne null.
  if (response.status === 204) {
    return null;
  }

  // Sinon, on retourne le JSON.
  return response.json();
}

    modal.classList.add('active');

  closeBtn.addEventListener('click', fermer);

    if (event.key === 'Escape') {
      fermer();
    }
  });
}

// 19 — MAPPED TYPES

Mapped types et conditional types

Les mapped types et les conditional types font partie des outils avancés de TypeScript. Ils permettent de fabriquer des types automatiquement à partir d’autres types.

À quoi ça sert ?

Ces notions permettent de créer des types flexibles, réutilisables et très puissants. Elles sont utilisées dans beaucoup d’utility types comme Partial, Required, Readonly, ReturnType, Awaited, Pick, Omit, etc.

Comprendre keyof

Avant de comprendre les mapped types, il faut comprendre keyof. keyof récupère les clés d’un type sous forme d’union.

typescript

// Interface de base.
interface User {
  id: number;
  nom: string;
  email: string;
}

// keyof User récupère les clés du type User.
//
// Le résultat est équivalent à :
// 'id' | 'nom' | 'email'
type ClesUser = keyof User;

// Cette variable ne peut contenir qu'une clé existante de User.
const cle1: ClesUser = 'id';
const cle2: ClesUser = 'nom';

// Cette ligne serait refusée,
// car 'age' n'existe pas dans User.
// const cle3: ClesUser = 'age';
À retenir :

keyof transforme les noms de propriétés d’un type en union de chaînes. C’est la base de beaucoup de types avancés.

Mapped type simple

Un mapped type permet de parcourir les clés d’un type pour créer un nouveau type. La syntaxe ressemble à une boucle, mais au niveau des types.

typescript

// Mapped type générique.
// T représente le type de départ.
type Options<T> = {
  /*
    [K in keyof T] signifie :

    Pour chaque clé K présente dans T,
    crée une propriété dans le nouveau type.

    Le ? rend chaque propriété optionnelle.

    T[K] récupère le type de la propriété correspondante.
  */
  [K in keyof T]?: T[K];
};

// Interface de départ.
interface User {
  id: number;
  nom: string;
  email: string;
}

// UserOptions est généré automatiquement depuis User.
//
// Il devient équivalent à :
// {
//   id?: number;
//   nom?: string;
//   email?: string;
// }
type UserOptions = Options<User>;

// Exemple valide :
// toutes les propriétés sont optionnelles.
const options: UserOptions = {
  nom: 'Julien'
};
Ce que fait Options<T> :

Il reprend toutes les propriétés du type T, conserve leur type, mais les rend optionnelles. C’est exactement l’idée derrière Partial<T>.

Recréer Partial<T>

Pour bien comprendre, on peut recréer une version simplifiée de Partial<T>.

typescript

// Version simplifiée de Partial<T>.
type MonPartial<T> = {
  // Pour chaque propriété de T,
  // on garde le même type mais on ajoute ?.
  [K in keyof T]?: T[K];
};

interface Article {
  id: number;
  titre: string;
  contenu: string;
  publie: boolean;
}

// ArticlePatch permet de modifier seulement une partie d'un Article.
type ArticlePatch = MonPartial<Article>;

// Exemple : on modifie seulement le titre.
const patch: ArticlePatch = {
  titre: 'Nouveau titre'
};

Mapped type avec readonly

Un mapped type peut aussi ajouter readonly à toutes les propriétés.

typescript

// Rend toutes les propriétés en lecture seule.
type MonReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

type ArticleLectureSeule = MonReadonly<Article>;

const article: ArticleLectureSeule = {
  id: 1,
  titre: 'TypeScript',
  contenu: 'Cours',
  publie: true
};

// Lecture autorisée.
console.log(article.titre);

// Modification interdite par TypeScript.
// article.titre = 'Nouveau titre';

Retirer readonly ou optional

TypeScript permet aussi de retirer certains modificateurs avec -readonly ou -?.

typescript

// Retire readonly de toutes les propriétés.
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// Rend toutes les propriétés obligatoires.
// Le -? retire le caractère optionnel.
type Obligatoire<T> = {
  [K in keyof T]-?: T[K];
};

interface Brouillon {
  readonly id?: number;
  titre?: string;
  contenu?: string;
}

// Toutes les propriétés deviennent obligatoires.
type BrouillonComplet = Obligatoire<Brouillon>;

// Toutes les propriétés perdent readonly.
type BrouillonMutable = Mutable<Brouillon>;
À retenir :

readonly ajoute la lecture seule. -readonly la retire. ? rend une propriété optionnelle. -? rend une propriété obligatoire.

Conditional type

Un conditional type fonctionne comme une condition, mais au niveau des types.

typescript

// Conditional type.
//
// Si T est compatible avec string,
// alors le type vaut true.
// Sinon, il vaut false.
type EstString<T> = T extends string ? true : false;

// Ici, string extends string est vrai.
// Donc A vaut true.
type A = EstString<string>;

// Ici, number extends string est faux.
// Donc B vaut false.
type B = EstString<number>;

// Autres exemples.
type C = EstString<'hello'>; // true
type D = EstString<boolean>; // false
Structure d’un conditional type :

T extends U ? X : Y signifie : si T est compatible avec U, alors utilise X, sinon utilise Y.

Conditional type avec infer

Le mot-clé infer permet à TypeScript de deviner un type à l’intérieur d’un autre type.

typescript

// Objectif : récupérer le type contenu dans un tableau.
//
// Si T est un tableau Array<U>,
// alors on récupère U.
// Sinon, on garde T.
type ElementDeTableau<T> = T extends Array<infer U> ? U : T;

// number[] est un tableau contenant des number.
// Donc Nombre vaut number.
type Nombre = ElementDeTableau<number[]>;

// string n'est pas un tableau.
// Donc Texte vaut string.
type Texte = ElementDeTableau<string>;

// string[] est un tableau contenant des string.
// Donc Mot vaut string.
type Mot = ElementDeTableau<string[]>;
Comprendre infer :

infer U demande à TypeScript : “si tu reconnais cette structure, récupère le type intérieur et appelle-le U”.

Récupérer le retour d’une fonction

Avec infer, on peut aussi récupérer automatiquement le type de retour d’une fonction. C’est le principe derrière ReturnType<T>.

typescript

// Type qui récupère le retour d'une fonction.
type MonReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function creerUser() {
  return {
    id: 1,
    nom: 'Julien',
    email: 'julien@example.com'
  };
}

// typeof creerUser récupère le type de la fonction.
// MonReturnType récupère le type de ce que la fonction retourne.
type UserCree = MonReturnType<typeof creerUser>;

// UserCree est équivalent à :
// {
//   id: number;
//   nom: string;
//   email: string;
// }
const user: UserCree = {
  id: 1,
  nom: 'Julien',
  email: 'julien@example.com'
};

Récupérer le type résolu d’une Promise

On peut aussi créer un type qui récupère ce qu’une Promise retourne une fois résolue. C’est l’idée derrière Awaited<T>.

typescript

// Type qui récupère le contenu d'une Promise.
type MonAwaited<T> = T extends Promise<infer R> ? R : T;

async function getArticle() {
  return {
    id: 1,
    titre: 'Mapped types',
    publie: true
  };
}

// ReturnType<typeof getArticle> donne Promise<{ id, titre, publie }>.
// MonAwaited déballe la Promise et récupère le type final.
type ArticleResolue = MonAwaited<ReturnType<typeof getArticle>>;

const article: ArticleResolue = {
  id: 1,
  titre: 'Mapped types',
  publie: true
};

Conditional types distribués

Quand un conditional type reçoit une union, TypeScript applique souvent la condition à chaque membre de l’union séparément.

typescript

// Si T est une string, on garde T.
// Sinon, on retourne never.
type GarderString<T> = T extends string ? T : never;

// TypeScript applique la condition à chaque membre :
//
// string extends string ? string : never  => string
// number extends string ? number : never  => never
// boolean extends string ? boolean : never => never
//
// Résultat final : string
type SeulementString = GarderString<string | number | boolean>;

// Exemple similaire pour retirer les strings.
type RetirerString<T> = T extends string ? never : T;

// Résultat : number | boolean
type SansString = RetirerString<string | number | boolean>;
À quoi ça sert ?

Cette logique permet de filtrer des unions de types. C’est le principe utilisé par des utility types comme Extract et Exclude.

Exemple concret : type de réponse API

Les conditional types peuvent aider à transformer automatiquement les types selon leur forme.

typescript

// Type générique de réponse API.
type ApiResponse<T> = {
  success: boolean;
  data: T;
  error?: string;
};

// Type qui récupère seulement data depuis une réponse API.
type DataDeResponse<T> = T extends ApiResponse<infer D> ? D : never;

// Exemple de réponse utilisateur.
type UserResponse = ApiResponse<{
  id: number;
  nom: string;
}>;

// On extrait automatiquement le type contenu dans data.
type UserData = DataDeResponse<UserResponse>;

// UserData vaut :
// {
//   id: number;
//   nom: string;
// }

Mapped type avec changement de noms de clés

TypeScript permet aussi de transformer les noms de propriétés avec as.

typescript

// Objectif : créer automatiquement des getters.
//
// Pour chaque clé K,
// on crée une nouvelle clé getX.
type Getters<T> = {

interface Produit {

  prix: number;
  stock: number;

// {
//   getNom: () => string;
//   getPrix: () => number;
//   getStock: () => number;
// }

  getPrix: () => 49,
  getStock: () => 12

Attention :

Les mapped types et conditional types sont très puissants, mais il ne faut pas en abuser. Si un type devient trop difficile à lire, il peut compliquer le projet au lieu de l’aider.

Résumé rapide

Résumé simple :

// 20 — VALIDATION

Valider les données côté client

TypeScript sécurise ton code pendant le développement, mais il ne vérifie pas réellement les données quand le site est en train de fonctionner. Les données venant d’une API, d’un formulaire, du localStorage ou d’un fichier JSON doivent donc être validées au runtime, c’est-à-dire pendant l’exécution du programme.

À quoi ça sert ?

La validation côté client permet d’éviter les bugs liés aux données inattendues : propriété manquante, mauvais type, tableau invalide, champ vide, nombre négatif, réponse API incorrecte, etc.

Important :

TypeScript aide à écrire du code plus sûr, mais il disparaît après compilation. Dans le navigateur, il reste du JavaScript. Il faut donc vérifier les données sensibles ou externes avec du code JavaScript réel.

TypeScript ne valide pas automatiquement les API

Quand tu écris as User, tu dis à TypeScript de croire que la donnée est un User. Mais cela ne vérifie pas vraiment la structure de la donnée.

typescript

// Interface attendue.
interface User {
  id: number;
  nom: string;
}

// Exemple de donnée venant d'une API.
// TypeScript ne peut pas être certain de sa structure.
const data: unknown = await fetch('/api/user').then((r) => r.json());

// Mauvais réflexe si on ne valide jamais :
// const user = data as User;

// Le "as User" force TypeScript à croire que data est un User,
// mais cela ne vérifie rien au runtime.
Piège classique :

as User ne transforme pas la donnée et ne la vérifie pas. C’est seulement une indication donnée à TypeScript.

Validation manuelle avec un type guard

Un type guard est une fonction qui vérifie une donnée inconnue et informe TypeScript de son type si la vérification réussit.

typescript

// Interface représentant un utilisateur valide.
interface User {
  id: number;
  nom: string;
}

// Type guard personnalisé.
//
// La syntaxe "value is User" signifie :
// si cette fonction retourne true,
// alors TypeScript peut considérer value comme un User.
function estUser(value: unknown): value is User {
  /*
    Première vérification :
    on s'assure que value est bien un objet.

    typeof null retourne aussi "object",
    donc il faut vérifier value === null.
  */
  if (typeof value !== 'object' || value === null) {
    return false;
  }

  /*
    À ce stade, on sait que value est un objet,
    mais TypeScript ne connaît pas encore ses propriétés.

    Record<string, unknown> signifie :
    objet avec des clés string et des valeurs inconnues.
  */
  const obj = value as Record<string, unknown>;

  /*
    On vérifie les propriétés attendues :
    - id doit être un number
    - nom doit être une string
  */
  return typeof obj.id === 'number'
    && typeof obj.nom === 'string';
}

// Donnée inconnue venant d'une API.
const data: unknown = await fetch('/api/user').then((r) => r.json());

// On valide avant d'utiliser.
if (estUser(data)) {
  // Ici, TypeScript sait que data est un User.
  console.log(data.nom);
} else {
  console.error('Format API invalide');
}
À retenir :

Un type guard vérifie réellement les données pendant l’exécution et améliore aussi le typage TypeScript dans le bloc if.

Valider un objet avec plus de propriétés

Plus ton objet est complexe, plus il faut vérifier chaque propriété importante.

typescript

// Interface représentant un article.
interface Article {
  id: number;
  titre: string;
  contenu: string;
  publie: boolean;
  tags: string[];
}

// Type guard pour vérifier un Article.
function estArticle(value: unknown): value is Article {
  if (typeof value !== 'object' || value === null) {
    return false;
  }

  const obj = value as Record<string, unknown>;

  /*
    On vérifie :
    - id : number
    - titre : string
    - contenu : string
    - publie : boolean
    - tags : tableau
  */
  return typeof obj.id === 'number'
    && typeof obj.titre === 'string'
    && typeof obj.contenu === 'string'
    && typeof obj.publie === 'boolean'
    && Array.isArray(obj.tags)
    && obj.tags.every((tag) => typeof tag === 'string');
}

// Exemple d'utilisation.
const articleData: unknown = await fetch('/api/article/1').then((r) => r.json());

if (estArticle(articleData)) {
  console.log(articleData.titre);
  console.log(articleData.tags);
} else {
  console.error('Article invalide');
}

Valider un tableau d’objets

Quand une API retourne une liste, il faut vérifier que la donnée est bien un tableau, puis vérifier chaque élément du tableau.

typescript

// Type guard pour vérifier un tableau d'articles.
function estListeArticles(value: unknown): value is Article[] {
  /*
    On vérifie d'abord que value est un tableau.
  */
  if (!Array.isArray(value)) {
    return false;
  }

  /*
    every() vérifie que chaque élément du tableau
    respecte le type Article.
  */
  return value.every((item) => estArticle(item));
}

// Exemple avec une API qui retourne plusieurs articles.
const articlesData: unknown = await fetch('/api/articles').then((r) => r.json());

if (estListeArticles(articlesData)) {
  // Ici, TypeScript sait que articlesData est un Article[].
  articlesData.forEach((article) => {
    console.log(article.titre);
  });
} else {
  console.error('Liste d’articles invalide');
}
Bon réflexe :

Pour valider un tableau, utilise souvent Array.isArray(), puis every() avec un type guard.

Valider un objet imbriqué

Si un objet contient un autre objet, il vaut mieux créer un type guard séparé pour chaque niveau.

typescript

// Auteur imbriqué dans un article.
interface Auteur {
  id: number;
  nom: string;
}

interface ArticleComplet {
  id: number;
  titre: string;
  auteur: Auteur;

  if (typeof value !== 'object' || value === null) {

  }

    && typeof obj.nom === 'string';
}

// Type guard pour ArticleComplet.

  if (typeof value !== 'object' || value === null) {
    return false;

Créer une fonction fetch validée

On peut créer une fonction générique qui récupère des données depuis une API, puis valide la réponse avec un type guard.

typescript

// Type d'un validateur.
// Il reçoit unknown et retourne true si la donnée est du type T.
type Validateur<T> = (value: unknown) => value is T;

// Fonction fetch sécurisée.
async function fetchValide<T>(
  url: string,
  validateur: Validateur<T>
): Promise<T> {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error(`Erreur HTTP ${response.status}`);
  }

  const data: unknown = await response.json();

  /*
    On valide la donnée avant de la retourner.
  */
  if (!validateur(data)) {
    throw new Error('Format API invalide');
  }

  /*
    Ici, TypeScript sait que data est bien de type T.
  */
  return data;
}

// Exemple d'utilisation avec un User.
async function chargerUser(): Promise<User> {
  return fetchValide<User>('/api/user', estUser);
}
Pourquoi cette fonction est intéressante ?

Elle centralise la logique : requête HTTP, vérification response.ok, conversion JSON, validation runtime et retour typé.

Retourner un résultat au lieu de lancer une erreur

Parfois, au lieu de faire un throw, on peut retourner un objet résultat. Cela permet de gérer les erreurs plus doucement dans l’interface.

typescript

// Type de résultat.
// Soit tout va bien : ok true + data.
// Soit il y a une erreur : ok false + error.
type Resultat<T> =
  | { ok: true; data: T }
  | { ok: false; error: string };

// Fonction qui essaie de valider un User.
function validerUser(value: unknown): Resultat<User> {
  if (estUser(value)) {
    return {
      ok: true,
      data: value
    };
  }

  return {
    ok: false,
    error: 'Utilisateur invalide'
  };
}

// Exemple.
const resultat = validerUser(data);

if (resultat.ok) {
  console.log(resultat.data.nom);
} else {
  console.error(resultat.error);
}

Créer de petits validateurs réutilisables

Pour éviter de répéter toujours les mêmes vérifications, tu peux créer de petites fonctions simples.

typescript

// Vérifie qu'une donnée est un objet non null.
function estObjet(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}

// Vérifie qu'une donnée est une string non vide.
function estStringNonVide(value: unknown): value is string {
  return typeof value === 'string' && value.trim().length > 0;
}

// Vérifie qu'une donnée est un nombre positif.
function estNombrePositif(value: unknown): value is number {
  return typeof value === 'number' && Number.isFinite(value) && value >= 0;
}

// Exemple avec un produit.
interface Produit {
  nom: string;
  prix: number;
}

function estProduit(value: unknown): value is Produit {
  if (!estObjet(value)) {
    return false;
  }

  return estStringNonVide(value.nom)
    && estNombrePositif(value.prix);
}

Résumé simple :

// 21 — PERFORMANCE

Performance front-end

Une interface performante limite les recalculs inutiles, les animations coûteuses, les requêtes trop fréquentes et les manipulations DOM répétées. L’objectif est de garder une page fluide, rapide et agréable à utiliser.

À quoi ça sert ?

La performance front-end est importante pour les menus, formulaires, recherches, tableaux dynamiques, graphiques, animations, applications mobiles, PWA et sites riches en JavaScript.

À retenir :

Pour améliorer les performances, il faut éviter de faire trop de travail trop souvent. Les techniques comme debounce, throttle, requestAnimationFrame, la limitation des accès DOM et le chargement différé sont très utiles.

Reflow, repaint et composition

Quand tu modifies une page, le navigateur peut devoir recalculer la mise en page, redessiner des éléments ou simplement composer une nouvelle image.

Notion Rôle Coût
Reflow Recalcule la taille et la position des éléments. Coûteux
Repaint Redessine les couleurs, bordures, ombres, textes. Moyen à coûteux
Composite Assemble les calques visuels. Souvent plus léger
Bon réflexe :

Pour les animations, privilégie transform et opacity. Évite d’animer trop souvent width, height, top, left ou margin.

Debounce

Le debounce attend que l’utilisateur arrête une action pendant un certain délai avant d’exécuter une fonction.

Exemple concret :

Dans une barre de recherche, tu ne veux pas appeler l’API à chaque lettre tapée. Tu attends que l’utilisateur arrête de taper pendant 300 ou 400 ms, puis tu lances la recherche.

javascript

// Fonction debounce générique.
// Elle reçoit une fonction fn et un délai.
function debounce(fn, delay = 300) {
  /*
    timer stocke l'identifiant du setTimeout.

    Il est conservé grâce à une closure :
    la fonction retournée garde accès à timer.
  */
  let timer;

  /*
    On retourne une nouvelle fonction.

    Cette fonction sera appelée à la place de la fonction originale.
  */
  return (...args) => {
    /*
      À chaque nouvel appel, on annule le timer précédent.

      Cela signifie :
      "tant que l'utilisateur continue d'agir,
      on repousse l'exécution".
    */
    clearTimeout(timer);

    /*
      On crée un nouveau timer.

      Si aucun nouvel appel n'arrive avant la fin du délai,
      alors fn est exécutée.
    */
    timer = setTimeout(() => {
      fn(...args);
    }, delay);
  };
}

Debounce sur une recherche API

Voici un exemple typique avec un champ de recherche.

javascript

// Fonction de recherche avec debounce.
// Elle ne sera vraiment exécutée que lorsque l'utilisateur
// aura arrêté de taper pendant 400 ms.
const rechercher = debounce(async (event) => {
  // On récupère la valeur saisie.
  const q = event.target.value.trim();

  // Si la recherche est vide, on évite une requête inutile.
  if (q === '') {
    console.log('Recherche vide');
    return;
  }

  /*
    encodeURIComponent sécurise la valeur dans l'URL.

    Exemple :
    "js avancé" devient "js%20avanc%C3%A9".
  */
  const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`);

  // On transforme la réponse en JSON.
  const data = await res.json();

  console.log(data);
}, 400);

// On récupère l'input de recherche.
const searchInput = document.querySelector('#search');

// On vérifie que l'élément existe avant d'ajouter l'événement.
if (searchInput) {
  /*
    input se déclenche à chaque modification du champ.

    Grâce au debounce, la recherche ne partira pas à chaque caractère,
    mais seulement après une pause.
  */
  searchInput.addEventListener('input', rechercher);
}
Quand utiliser debounce ?

Utilise debounce pour une recherche, une validation de formulaire, un autosave, un redimensionnement de fenêtre ou une action qui doit attendre que l’utilisateur ait terminé.

Throttle

Le throttle limite une fonction à une exécution maximum pendant un intervalle donné. Contrairement au debounce, il n’attend pas forcément la fin de l’action.

Exemple concret :

Pendant un scroll, l’événement peut se déclencher énormément de fois. Avec un throttle, tu peux dire : “exécute cette fonction au maximum une fois toutes les 250 ms”.

javascript

// Fonction throttle générique.
// Elle limite le nombre d'exécutions d'une fonction.
function throttle(fn, delay = 200) {
  /*
    last mémorise le dernier moment où la fonction a été exécutée.
  */
  let last = 0;

  return (...args) => {
    /*
      Date.now() donne le timestamp actuel en millisecondes.
    */
    const now = Date.now();

    /*
      Si assez de temps s'est écoulé depuis le dernier appel,
      on exécute la fonction.
    */
    if (now - last >= delay) {
      // On met à jour le dernier moment d'exécution.
      last = now;

      // On exécute la fonction originale.
      fn(...args);
    }
  };
}

Throttle sur le scroll

javascript

/*
  On écoute le scroll de la fenêtre.

  Sans throttle, ce callback pourrait être appelé
  des dizaines de fois par seconde.
*/
window.addEventListener('scroll', throttle(() => {
  console.log(window.scrollY);
}, 250));
Quand utiliser throttle ?

Utilise throttle pour le scroll, le resize, le mouvement de souris, le suivi de progression, ou une action répétée qui doit rester limitée.

Debounce vs throttle

Technique Principe Usage idéal
debounce Attend une pause avant d’exécuter. Recherche, autosave, validation de formulaire.
throttle Limite l’exécution à intervalle régulier. Scroll, resize, mousemove, progression.

requestAnimationFrame pour les animations

Pour les animations visuelles calculées en JavaScript, utilise plutôt requestAnimationFrame(). Le navigateur synchronise alors le calcul avec le rendu de l’écran.

javascript

// Élément à déplacer.
const box = document.querySelector('.box');

let position = 0;

function animer() {
  if (!box) {
    return;
  }

  // On modifie une variable.
  position += 2;

  /*
    transform est généralement performant pour les animations.
    Il évite souvent de recalculer toute la mise en page.
  */
  box.style.transform = `translateX(${position}px)`;

  /*
    Tant que la position est inférieure à 300,
    on demande une nouvelle frame.
  */
  if (position < 300) {
    requestAnimationFrame(animer);
  }
}

// Lance l'animation.
requestAnimationFrame(animer);
Bon réflexe :

Pour animer une position, préfère transform: translate() plutôt que left ou top.

Limiter les accès au DOM

Accéder au DOM et le modifier peut être coûteux si tu le fais trop souvent. Il vaut mieux regrouper les modifications.

javascript

// Mauvais réflexe :
// on modifie le DOM à chaque tour de boucle.
const liste = document.querySelector('#liste');

const items = ['HTML', 'CSS', 'JavaScript', 'TypeScript'];

if (liste) {

    const li = document.createElement('li');

javascript

// Meilleur réflexe :
// on prépare les éléments dans un DocumentFragment,
// puis on ajoute tout au DOM en une seule fois.
const listeOptimisee = document.querySelector('#liste');

const langages = ['HTML', 'CSS', 'JavaScript', 'TypeScript'];

if (listeOptimisee) {
  /*
    DocumentFragment est un conteneur temporaire.
    Les ajouts dans le fragment ne modifient pas directement la page.
  */
  const fragment = document.createDocumentFragment();

  langages.forEach((langage) => {
    const li = document.createElement('li');
    li.textContent = langage;

    fragment.appendChild(li);
  });

  /*
    Une seule insertion dans le DOM final.
  */
  listeOptimisee.appendChild(fragment);

Annuler une requête inutile avec AbortController

Quand l’utilisateur tape une nouvelle recherche, l’ancienne requête peut devenir inutile. AbortController permet de l’annuler.

javascript

// Contrôleur de requête en cours.
let searchController = null;

async function rechercherAPI(terme) {
  /*
    Si une ancienne requête existe,
    on l'annule avant d'en lancer une nouvelle.
  */
  if (searchController) {
    searchController.abort();
  }

  // Nouveau contrôleur pour la nouvelle requête.
  searchController = new AbortController();

  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(terme)}`, {
      signal: searchController.signal
    });

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const data = await response.json();

    console.log(data);
  } catch (err) {
    /*
      AbortError signifie que la requête a été annulée volontairement.
      Ce n'est pas forcément une vraie erreur utilisateur.
    */
    if (err.name === 'AbortError') {
      console.log('Requête annulée');
      return;
    }

    console.error('Erreur recherche :', err);
  }
}

Mesurer le temps d’exécution

Avant d’optimiser, il faut mesurer. performance.now() permet de mesurer précisément le temps pris par une opération.

javascript

// Début de la mesure.

  total += i;

// Fin de la mesure.

console.log(`Temps écoulé : ${fin - debut} ms`);
console.log(total);

Petites bonnes pratiques

  • Évite les calculs lourds dans les événements très fréquents.
  • Utilise debounce pour les recherches et validations.
  • Utilise throttle pour le scroll et le resize.
  • Utilise requestAnimationFrame pour les animations JS.
  • Prépare les éléments dans un DocumentFragment avant de les insérer.
  • Évite d’animer width, height, top ou left.
  • Privilégie transform et opacity.
  • Annule les requêtes devenues inutiles avec AbortController.
  • Mesure avant d’optimiser.

Accessibilité et interactions

Une interface moderne doit rester utilisable par tout le monde : à la souris, au clavier, sur mobile, avec un lecteur d’écran, avec une navigation réduite, ou avec des besoins visuels particuliers.

À quoi ça sert ?

L’accessibilité permet de créer des interfaces plus claires, plus solides et plus professionnelles. Un bouton doit être compréhensible, une modale doit pouvoir se fermer au clavier, un menu doit indiquer s’il est ouvert ou fermé, et un formulaire doit expliquer ses erreurs.

À retenir :

Avant d’ajouter de l’ARIA partout, commence par utiliser le bon HTML : <button> pour un bouton, <label> pour un champ, <nav> pour une navigation, <main> pour le contenu principal. L’ARIA complète le HTML, mais ne doit pas remplacer une mauvaise structure.

Le HTML sémantique donne du sens à la page. Les lecteurs d’écran et les navigateurs comprennent mieux la structure.

JavaScript pour ouvrir et fermer une modale

JavaScript doit gérer l’état de la modale : affichée ou cachée. Il peut aussi replacer le focus pour améliorer la navigation clavier.

javascript

// On récupère les éléments nécessaires.
const openModal = document.querySelector('#openModal');
const closeModal = document.querySelector('#closeModal');
const modal = document.querySelector('#modal');

// Cette variable servira à mémoriser le dernier élément qui avait le focus.
let lastFocusedElement = null;

function ouvrirModal() {
  if (!modal || !closeModal) {
    return;
  }

  /*
    On mémorise l'élément actuellement sélectionné au clavier.

    Cela permettra de lui rendre le focus quand la modale sera fermée.
  */
  lastFocusedElement = document.activeElement;

  /*
    hidden = false affiche la modale.
  */
  modal.hidden = false;

  /*
    On met le focus sur le bouton de fermeture.

    Comme ça, un utilisateur clavier arrive directement
    dans la modale.
  */
  closeModal.focus();
}

function fermerModal() {
  if (!modal) {
    return;
  }

  /*
    hidden = true cache la modale.
  */
  modal.hidden = true;

  /*
    On rend le focus à l'élément qui avait ouvert la modale.
  */
  if (lastFocusedElement) {
    lastFocusedElement.focus();
  }
}

if (openModal && closeModal && modal) {
  openModal.addEventListener('click', ouvrirModal);
  closeModal.addEventListener('click', fermerModal);

  /*
    On ferme la modale avec Escape.
  */
  document.addEventListener('keydown', (event) => {
    if (event.key === 'Escape' && !modal.hidden) {
      fermerModal();
    }
  });
}
À retenir :

Une modale ne doit pas seulement apparaître visuellement. Elle doit aussi gérer le focus, être nommée correctement et pouvoir être fermée facilement.

États ARIA dynamiques

Certains composants changent d’état : menu ouvert ou fermé, accordéon déplié ou replié, bouton actif ou non. Les attributs ARIA permettent d’indiquer ces changements aux technologies d’assistance.

html

  aria-expanded indique si le menu est ouvert ou fermé.
  aria-controls indique quel élément est contrôlé par ce bouton.
-->
<button

  aria-expanded="false"
  aria-controls="sidebar"
>
  Menu
</button>

  <nav aria-label="Menu secondaire">
    <a href="#html">HTML</a>
    <a href="#css">CSS</a>
    <a href="#javascript">JavaScript</a>
  </nav>

javascript

// On récupère le bouton et la sidebar.
const bouton = document.querySelector('#menuToggle');
const sidebar = document.querySelector('#sidebar');

function ouvrirMenu() {
  if (!bouton || !sidebar) {
    return;
  }

  /*
    On ajoute la classe CSS qui affiche le menu.
  */
  sidebar.classList.add('open');

  /*
    On indique aux lecteurs d'écran que le menu est ouvert.
  */
  bouton.setAttribute('aria-expanded', 'true');
}

function fermerMenu() {
  if (!bouton || !sidebar) {
    return;
  }

  /*
    On retire la classe CSS qui affiche le menu.
  */
  sidebar.classList.remove('open');

  /*
    On indique aux lecteurs d'écran que le menu est fermé.
  */
  bouton.setAttribute('aria-expanded', 'false');
}

function toggleMenu() {
  if (!bouton || !sidebar) {
    return;
  }

  /*
    On vérifie si le menu est déjà ouvert.
  */
  const isOpen = sidebar.classList.contains('open');

  if (isOpen) {
    fermerMenu();
  } else {
    ouvrirMenu();
  }
}

if (bouton && sidebar) {
  bouton.addEventListener('click', toggleMenu);
}

  accordionBtn.addEventListener('click', () => {
    /*
      On vérifie si le contenu est actuellement caché.

      Si c'est caché, on affiche.

    return;

    aria-invalid="true" indique que le champ contient une erreur.
